.NET / Web

ASP.NET Core

Microsoft's web framework for .NET. Open source, runs on Windows, Linux and macOS. First released in 2016.

What it is

ASP.NET Core is a framework for building web APIs and web sites in C#. It runs on .NET, the runtime that compiles and runs C# code. Your app is a normal program: dotnet run starts it, and it listens for HTTP requests itself.

A program has two phases. First, a WebApplicationBuilder collects settings and registers services in the dependency injection container. Then builder.Build() creates a WebApplication, and you add middleware and endpoints to it. app.Run() starts the web server, Kestrel.

Each request gets its own HttpContext object and travels through the middleware in the order you added it. The last step is your endpoint: a minimal API handler or a controller method.

TermMeaningIn the example
KestrelThe web server built into ASP.NET Core. It runs inside your process and turns bytes from the network into requests.Listens on port 8080 in the container
WebApplicationThe app object. The builder registers services; the app holds the middleware and endpoints.Program.cs
MiddlewareA function that gets the HttpContext and a next function. It can work before and after next, or not call it.RequestLoggingMiddleware
EndpointThe code that handles one route, for example GET /orders/{orderId}.OrderEndpoints.GetOrder

OptionsA typed C# class filled from configuration, such as appsettings.json and environment variables.OrderOptions
Main rule: every request goes through the middleware in the order of the app.Use... calls in Program.cs, then back out in reverse order. Wrong order is the most common ASP.NET Core bug.

The middleware pipeline and its order

Middleware code before await next(context) runs on the way in. Code after it runs on the way out, when the response is coming back. A middleware that does not call next ends the request there. This is called short-circuiting: the rest of the pipeline and the endpoint never run.

OrderMiddlewareWhat it doesWhy it is here
1UseForwardedHeadersReads X-Forwarded-Proto and X-Forwarded-For from the reverse proxyEverything after it sees the real scheme and client IP
2Request logging (yours)Sets a correlation ID, logs one line per requestOutermost, so it sees the final status code, including a 500
3UseExceptionHandlerCatches exceptions from all later middleware and returns a 500 responseIt can only catch what runs after it
4UseHsts, UseHttpsRedirectionRedirects http:// to https:// with a 307 statusBefore any real work
5UseRoutingPicks the endpoint for the URL and stores it on HttpContextAuthorization needs to know the endpoint and its rules
6UseAuthenticationReads the token or cookie and sets HttpContext.User. Never rejects a request.After routing, before authorization
7UseAuthorizationChecks the endpoint's policy. Returns 401 or 403 and stops.Needs both the endpoint and the user
8Endpoints (MapGet, MapControllers)Runs your handlerLast

Dependency injection lifetimes

You register each service with a lifetime. The lifetime decides how long one instance lives and who shares it. Each request gets its own scope, a small container that lives until the response is sent.

LifetimeInstancesRegister withUse for
SingletonOne for the whole app, shared by all requests and threadsAddSingletonCaches, TimeProvider, clients that are safe to share. Must be thread safe.
ScopedOne per requestAddScoped, AddDbContextDbContext, services that use it, data about the current user
TransientA new one every time it is asked forAddTransientSmall helpers with no state

A service may only depend on services that live as long or longer. A singleton that takes a scoped service in its constructor keeps that one instance forever. This mistake is called a captive dependency. With a DbContext, all requests then share one object that is not thread safe. In the Development environment, builder.Build() throws an error for this. In Production, the check is off, so the bug reaches users. The fix: make the consumer scoped, or inject IServiceScopeFactory and create a scope for each unit of work.

Routing, minimal APIs and controllers

A route template such as /orders/{orderId:int} has fixed parts, parameters in braces and constraints after a colon. A constraint only picks the route: /orders/abc gets 404, not a validation error. There are two ways to write endpoints. Both run on the same routing and middleware.

Model binding and validation

Model binding fills your handler's parameters from the request. ASP.NET Core decides the source from the parameter's type and name, or from an attribute.

SourceHow it is chosenExample
RouteThe name matches a {parameter} in the routeint orderId from /orders/42
Query stringA simple type that is not in the route, or [FromQuery]int page from ?page=2
Header[FromHeader(Name = "X-Correlation-ID")]string correlationId
JSON bodyA complex type. One per endpoint.CreateOrderRequest request
DI containerA registered service type, or [FromServices]OrderService orderService
Request itselfSpecial typesHttpContext, CancellationToken, ClaimsPrincipal

Broken JSON or a wrong type, such as "quantity": "two", returns 400 in both styles. Rules such as "quantity must be at least 1" are validation. Put [Required] and [Range] attributes on the model. Controllers check them for you. Minimal APIs check them since .NET 10, once you call AddValidation(). Rules that depend on settings or data, such as a maximum read from options, stay in the handler and return TypedResults.ValidationProblem.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. A client sends GET /orders/42 with a bearer token. Kestrel reads the HTTP request from the socket and creates an HttpContext for it.
  2. Request logging takes the X-Correlation-ID header, or the trace ID, puts it in a log scope, starts a timer and calls next.
  3. The exception handler calls next inside a try/catch. HTTPS redirection sees an https request and calls next.
  4. Routing matches /orders/42 to the route /orders/{orderId:int} and stores that endpoint on HttpContext. It does not run it yet.
  5. Authentication checks the token and sets HttpContext.User. Authorization reads the endpoint's rule, RequireAuthorization(), and lets the request through.
  6. The endpoint runs. Model binding turns "42" into int orderId. The DI container creates OrderService and AppDbContext for this request.
  7. The response passes back through every middleware in reverse order. Request logging writes one line with status 200 and the duration. The request's scope ends and AppDbContext is disposed.
  1. A client sends GET /orders/42 with no Authorization header, or with an expired token.
  2. The request passes logging, the exception handler and HTTPS. Routing picks the GetOrder endpoint.
  3. Authentication finds no valid token. It sets HttpContext.User to an anonymous user and calls next. It does not reject the request itself.
  4. The endpoint requires an authenticated user. Authorization asks the JWT scheme for a challenge: status 401 with WWW-Authenticate: Bearer. It does not call next.
  5. The endpoint never ran and no AppDbContext was created. Request logging records the 401. A valid token without the needed scope gets 403 instead.
  1. A client sends POST /orders. The exception handler calls the rest of the pipeline inside a try/catch.
  2. HTTPS, routing, authentication and authorization all pass. The CreateOrder handler runs.
  3. The database does not answer in time, and SaveChangesAsync throws. Nothing in the handler or the service catches it.
  4. The exception moves up through each middleware. Their code after await next does not run, except in finally blocks. The exception handler catches it and logs it at Error level with the stack trace.
  5. It writes a 500 response as problem details JSON with a traceId and no stack trace. Request logging's finally block logs status 500 with the same correlation ID.
  1. In Program.cs, AddDbContext<AppDbContext> registers the context as scoped, and AddScoped<OrderService> does the same for the service.
  2. Request A arrives and gets a new scope, HttpContext.RequestServices. The first service that needs AppDbContext creates #1. Everything else in request A gets the same #1.
  3. Request B arrives at the same time on another thread. Its own scope creates AppDbContext #2. The two requests never share tracked entities or a connection.
  4. Request A finishes. Its scope is disposed, which disposes AppDbContext #1 and returns its database connection to the pool.
  1. A developer registers PriceCacheWithCaptiveDbContext with AddSingleton. Its constructor takes an AppDbContext, which is scoped.
  2. The container creates the singleton once and gives it one AppDbContext. That context is never disposed. Every request that uses the cache uses this same context.
  3. Two requests use it at the same moment. DbContext is not thread safe, so EF Core throws "A second operation was started on this context instance". Tracked entities also pile up in memory.
  4. In Development, builder.Build() fails with "Cannot consume scoped service from singleton". In Production the check is off. The fix in PriceCache: take IServiceScopeFactory and create a scope for each refresh.

Problems it solves

  • Using every CPU coreOne process runs requests on a thread pool across all cores. async and await free the thread while a request waits for the database.
  • Choosing and wiring many librariesDependency injection, configuration, logging, authentication and validation ship with the framework.
  • Windows and IIS onlyRuns on Linux in containers, behind any reverse proxy.
  • Type errors found at runtimeC# checks types at compile time, including route handler parameters and options classes.
  • Short support windowsLong-term support (LTS) versions get fixes for 3 years.

Problems it introduces

  • Middleware order mistakes give no errorPutting UseAuthorization before UseRouting compiles and starts, but the rules are not checked as you expect.
  • Lifetime mistakes reach productionCaptive dependencies are only checked in Development.
  • Two ways to write endpointsMinimal APIs and controllers differ in filters, conventions and Native AOT support. Teams must pick one.
  • Blocking on async codeCalling .Result or .Wait() holds a thread pool thread. Under load the pool runs out of threads and all requests slow down.
  • Many built-in parts to learnHosting, options, DI and the pipeline each have their own rules before the first endpoint works.
  • Larger process than a small Node.js serviceStartup time and memory are higher, unless you use Native AOT with minimal APIs.

MiddlewareLogging/RequestLoggingMiddleware.csUses the caller's X-Correlation-ID if it is short enough, else the OpenTelemetry trace ID, else TraceIdentifier. The log scope adds the ID to every log line written during the request. The finally block logs even when an exception passes through.
using System.Diagnostics;

namespace ShopApi.Logging;

public class RequestLoggingMiddleware(RequestDelegate next, ILogger<RequestLoggingMiddleware> logger)
{
    private const string CorrelationIdHeader = "X-Correlation-ID";
    private const int MaxCorrelationIdLength = 64;

    public async Task InvokeAsync(HttpContext context)
    {
        var correlationId = ReadIncomingCorrelationId(context)
            ?? Activity.Current?.TraceId.ToString()
            ?? context.TraceIdentifier;
        context.Response.Headers[CorrelationIdHeader] = correlationId;

        using var logScope = logger.BeginScope(new Dictionary<string, object> { ["CorrelationId"] = correlationId });
        var startedAt = Stopwatch.GetTimestamp();
        try
        {
            await next(context);
        }
        finally
        {
            logger.LogInformation(
                "{Method} {Path} responded {StatusCode} in {ElapsedMilliseconds:0} ms",
                context.Request.Method,
                context.Request.Path,
                context.Response.StatusCode,
                Stopwatch.GetElapsedTime(startedAt).TotalMilliseconds);
        }
    }

    private static string? ReadIncomingCorrelationId(HttpContext context)
    {
        var incomingId = context.Request.Headers[CorrelationIdHeader].FirstOrDefault();
        return incomingId is { Length: > 0 and <= MaxCorrelationIdLength } ? incomingId : null;
    }
}
MiddlewareErrors/ConcurrencyConflictHandler.csUseExceptionHandler() plus AddProblemDetails() already turns any exception into a 500 problem details response with a traceId. An IExceptionHandler maps chosen exception types to other status codes. Returning false leaves the default 500, and the middleware logs the exception. In .NET 10, an exception that a handler handles (returns true) is not logged by default.
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.EntityFrameworkCore;

namespace ShopApi.Errors;

public class ConcurrencyConflictHandler(IProblemDetailsService problemDetailsService) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext httpContext, Exception exception, CancellationToken cancellationToken)
    {
        if (exception is not DbUpdateConcurrencyException)
        {
            return false;
        }

        httpContext.Response.StatusCode = StatusCodes.Status409Conflict;
        return await problemDetailsService.TryWriteAsync(new ProblemDetailsContext
        {
            HttpContext = httpContext,
            Exception = exception,
            ProblemDetails = { Title = "The order was changed by another request." },
        });
    }
}
MiddlewareHosting/HttpsSetup.csBehind a proxy that handles TLS, the app only sees plain HTTP. UseForwardedHeaders, first in Program.cs, restores the real scheme from X-Forwarded-Proto, or the redirect would loop. Add your proxy's network to KnownIPNetworks: by default only localhost is trusted. HSTS tells browsers to use https for a year, so it is off in Development.
using Microsoft.AspNetCore.HttpOverrides;

namespace ShopApi.Hosting;

public static class HttpsSetup
{
    public static IServiceCollection AddShopHttps(this IServiceCollection services)
    {
        services.Configure<ForwardedHeadersOptions>(options =>
        {
            options.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto;
            options.KnownIPNetworks.Add(System.Net.IPNetwork.Parse("10.0.0.0/8"));
        });
        services.AddHttpsRedirection(options => options.HttpsPort = 443);
        services.AddHsts(options => options.MaxAge = TimeSpan.FromDays(365));
        return services;
    }

    public static WebApplication UseShopHttps(this WebApplication app)
    {
        if (!app.Environment.IsDevelopment())
        {
            app.UseHsts();
        }
        app.UseHttpsRedirection();
        return app;
    }
}
MiddlewareRouting/EndpointInfoMiddleware.csPlaced after UseRouting, so GetEndpoint() returns the matched endpoint and RouteValues holds orderId. Authorization reads the same endpoint to find its rules. If no route matches, the endpoint is null and the response is 404.
namespace ShopApi.Routing;

public class EndpointInfoMiddleware(RequestDelegate next, ILogger<EndpointInfoMiddleware> logger)
{
    public async Task InvokeAsync(HttpContext context)
    {
        var endpoint = context.GetEndpoint();
        if (endpoint is null)
        {
            logger.LogDebug("No endpoint matches {Path}", context.Request.Path);
        }
        else
        {
            logger.LogDebug("Matched {Endpoint} with route values {RouteValues}", endpoint.DisplayName, context.Request.RouteValues);
        }

        await next(context);
    }
}

MiddlewareAuth/AuthorizationSetup.csA named policy. The scope claim is one string with scopes separated by spaces, so the policy splits it. No user: 401. A user without the scope: 403.
namespace ShopApi.Auth;

public static class AuthorizationSetup
{
    public const string WriteOrdersPolicy = "orders:write";

    public static IServiceCollection AddShopAuthorization(this IServiceCollection services)
    {
        services.AddAuthorizationBuilder()
            .AddPolicy(WriteOrdersPolicy, policy => policy
                .RequireAuthenticatedUser()
                .RequireAssertion(context => HasScope(context.User, "orders:write")));
        return services;
    }

    private static bool HasScope(System.Security.Claims.ClaimsPrincipal user, string requiredScope)
    {
        var grantedScopes = user.FindFirst("scope")?.Value.Split(' ') ?? [];
        return grantedScopes.Contains(requiredScope);
    }
}
EndpointsOrders/OrderEndpoints.csModel binding fills each parameter: orderId from the route, request from the JSON body, services from DI, CancellationToken from the request. AddValidation() checks the attributes on CreateOrderRequest before the handler runs. The maximum comes from options, so the handler checks it and returns a 400 validation problem.
using System.ComponentModel.DataAnnotations;
using Microsoft.AspNetCore.Http.HttpResults;
using Microsoft.Extensions.Options;
using ShopApi.Auth;

namespace ShopApi.Orders;

public static class OrderEndpoints
{
    public static void MapOrderEndpoints(this IEndpointRouteBuilder app)
    {
        var orders = app.MapGroup("/orders").RequireAuthorization();

        orders.MapGet("/{orderId:int}", GetOrder).WithName("GetOrder");
        orders.MapPost("", CreateOrder).RequireAuthorization(AuthorizationSetup.WriteOrdersPolicy);
    }

    private static async Task<Results<Ok<OrderResponse>, NotFound>> GetOrder(
        int orderId, OrderService orderService, CancellationToken cancellationToken)
    {
        var order = await orderService.FindAsync(orderId, cancellationToken);
        return order is null ? TypedResults.NotFound() : TypedResults.Ok(order);
    }

    private static async Task<Results<CreatedAtRoute<OrderResponse>, ValidationProblem>> CreateOrder(
        CreateOrderRequest request,
        OrderService orderService,
        IOptions<OrderOptions> orderOptions,
        CancellationToken cancellationToken)
    {
        var maxQuantity = orderOptions.Value.MaxQuantityPerOrder;
        if (request.Quantity > maxQuantity)
        {
            return TypedResults.ValidationProblem(new Dictionary<string, string[]>
            {
                ["quantity"] = [$"Quantity must be at most {maxQuantity}."],
            });
        }

        var order = await orderService.CreateAsync(request, cancellationToken);
        return TypedResults.CreatedAtRoute(order, "GetOrder", new { orderId = order.Id });
    }
}

public record CreateOrderRequest(
    [Required, StringLength(20)] string ProductCode,
    [Range(1, 1000)] int Quantity);
EndpointsOrders/OrdersController.csThe same two endpoints as a controller, at /api/orders. A real app picks one style. [ApiController] checks the [Required] and [Range] attributes before the method runs and returns 400 if they fail.
using System.ComponentModel.DataAnnotations;
using Microsoft.AspNetCore.Authorization;
using Microsoft.AspNetCore.Mvc;
using ShopApi.Auth;

namespace ShopApi.Orders;

[ApiController]
[Route("api/orders")]
[Authorize]
public class OrdersController(OrderService orderService) : ControllerBase
{
    [HttpGet("{orderId:int}")]
    public async Task<ActionResult<OrderResponse>> GetOrder(int orderId, CancellationToken cancellationToken)
    {
        var order = await orderService.FindAsync(orderId, cancellationToken);
        if (order is null)
        {
            return NotFound();
        }
        return order;
    }

    [HttpPost]
    [Authorize(Policy = AuthorizationSetup.WriteOrdersPolicy)]
    public async Task<ActionResult<OrderResponse>> CreateOrder(CreateOrderForm form, CancellationToken cancellationToken)
    {
        var order = await orderService.CreateAsync(new CreateOrderRequest(form.ProductCode, form.Quantity), cancellationToken);
        return CreatedAtAction(nameof(GetOrder), new { orderId = order.Id }, order);
    }
}

public class CreateOrderForm
{
    [Required, StringLength(20)]
    public string ProductCode { get; set; } = "";

    [Range(1, 100)]
    public int Quantity { get; set; }
}

using Microsoft.EntityFrameworkCore;
using ShopApi.Data;

namespace ShopApi.Orders;

public class OrderService(AppDbContext dbContext, TimeProvider timeProvider, ILogger<OrderService> logger)
{
    public async Task<OrderResponse?> FindAsync(int orderId, CancellationToken cancellationToken)
    {
        return await dbContext.Orders
            .Where(order => order.Id == orderId)
            .Select(order => new OrderResponse(order.Id, order.ProductCode, order.Quantity, order.CreatedAt))
            .SingleOrDefaultAsync(cancellationToken);
    }

    public async Task<OrderResponse> CreateAsync(CreateOrderRequest request, CancellationToken cancellationToken)
    {
        var order = new Order
        {
            ProductCode = request.ProductCode,
            Quantity = request.Quantity,
            CreatedAt = timeProvider.GetUtcNow(),
        };
        dbContext.Orders.Add(order);
        await dbContext.SaveChangesAsync(cancellationToken);

        logger.LogInformation("Order {OrderId} created for product {ProductCode}", order.Id, order.ProductCode);
        return new OrderResponse(order.Id, order.ProductCode, order.Quantity, order.CreatedAt);
    }
}

public record OrderResponse(int Id, string ProductCode, int Quantity, DateTimeOffset CreatedAt);

using Microsoft.EntityFrameworkCore;
using ShopApi.Data;

namespace ShopApi.Pricing;

public class PriceCacheWithCaptiveDbContext(AppDbContext dbContext)
{
    public Task<decimal> FindPriceAsync(string productCode, CancellationToken cancellationToken) =>
        dbContext.Products
            .Where(product => product.Code == productCode)
            .Select(product => product.Price)
            .SingleAsync(cancellationToken);
}

public class PriceCache(IServiceScopeFactory scopeFactory, TimeProvider timeProvider)
{
    private static readonly TimeSpan RefreshInterval = TimeSpan.FromMinutes(5);
    private Dictionary<string, decimal> pricesByProductCode = [];
    private DateTimeOffset loadedAt = DateTimeOffset.MinValue;

    public async Task<decimal?> FindPriceAsync(string productCode, CancellationToken cancellationToken)
    {
        if (timeProvider.GetUtcNow() - loadedAt > RefreshInterval)
        {
            await RefreshAsync(cancellationToken);
        }
        return pricesByProductCode.TryGetValue(productCode, out var price) ? price : null;
    }

    private async Task RefreshAsync(CancellationToken cancellationToken)
    {
        await using var scope = scopeFactory.CreateAsyncScope();
        var dbContext = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        pricesByProductCode = await dbContext.Products.ToDictionaryAsync(product => product.Code, product => product.Price, cancellationToken);
        loadedAt = timeProvider.GetUtcNow();
    }
}
