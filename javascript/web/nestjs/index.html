NestJS Overview

A framework for Node.js servers that adds modules, dependency injection and a fixed request pipeline on top of Express or Fastify. Examples use NestJS 12.

What it is

With Express you decide how to organise the code. NestJS decides for you: each feature is a module with controllers for HTTP routes and providers (services) for the work. Nest creates every class at startup and passes each one the services it needs.

Each request then passes through steps in a fixed order: middleware, guards, interceptors, pipes, the handler, and on errors an exception filter. Each step has one job.

TopicKey ideaCommon mistake
Modules and providersList a class in a module; write what it needs as constructor parameters. Nest reads their types from compiler metadata and injects them. A provider is private unless its module exports it.Forgetting exports, or running the code with a tool that drops decorator metadata
Request lifecycleMiddleware, then guards (may it pass?), interceptors (before and after), pipes (validate input), the handler, and exception filters for errors.Putting authorization or validation in the handler
Main rule: one module per feature, services in the default scope, and each concern in its own step: authorization in a guard, validation in a pipe, error format in one global filter.

Problems it solves

  • No structure in large appsModules give each feature a boundary and a public part.
  • Wiring objects by handNest creates services and injects them, and tests can swap one for a fake.
  • Checks repeated in handlersGuards and pipes run before every route that declares them.

Problems it introduces

  • More concepts and filesModules, providers, decorators and five kinds of request step.
  • Depends on compiler metadataTools that skip decorator metadata break injection without an error at startup.
  • Behaviour spread over decoratorsWhat a route does depends on app, controller and method level settings.
Modulesorders.module.tsThe module lists its controller and its service. Nest sees that the controller's constructor needs an OrdersService, creates one and passes it in.
import { Controller, Injectable, Module, Post, Body } from "@nestjs/common";

@Injectable()
export class OrdersService {
  create(order: { customerId: string }) {
    return { orderId: "o-1", ...order };
  }
}

@Controller("orders")
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post()
  create(@Body() order: { customerId: string }) {
    return this.ordersService.create(order);
  }
}

@Module({ controllers: [OrdersController], providers: [OrdersService] })
export class OrdersModule {}
Middlewarerequest-context.tsThe rest of the request runs inside requestContext.run, so every later step and log line can read the request ID.
import { AsyncLocalStorage } from "node:async_hooks";
import { randomUUID } from "node:crypto";
import { Injectable, type NestMiddleware } from "@nestjs/common";
import type { NextFunction, Request, Response } from "express";

export const requestContext = new AsyncLocalStorage<{ requestId: string }>();

@Injectable()
export class RequestContextMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const requestId = req.header("x-request-id") ?? randomUUID();
    res.setHeader("x-request-id", requestId);
    requestContext.run({ requestId }, next);
  }
}
Guardadmin.guard.tsReturning false makes Nest answer 403. The handler, pipes and interceptors do not run.
import { type CanActivate, type ExecutionContext, Injectable } from "@nestjs/common";

@Injectable()
export class AdminGuard implements CanActivate {
  canActivate(context: ExecutionContext): boolean {
    const user = context.switchToHttp().getRequest().user as { roles: string[] } | undefined;
    return user?.roles.includes("admin") ?? false;
  }
}
Pipecreate-order.dto.tsThe global ValidationPipe checks these decorators on every request body of this type and answers 400 if any rule fails.
import { IsInt, IsString, Min } from "class-validator";

export class CreateOrderDto {
  @IsString()
  customerId!: string;

  @IsInt()
  @Min(1)
  quantity!: number;
}
Controllerorders.controller.tsBy the time this method runs, the guard has checked the role and the pipe has checked the body. The method only does the route's work.
import { Body, Controller, Post, UseGuards } from "@nestjs/common";
import { AdminGuard } from "./admin.guard.js";
import { CreateOrderDto } from "./create-order.dto.js";
import { OrdersService } from "./orders.service.js";

@Controller("orders")
@UseGuards(AdminGuard)
export class OrdersController {
  constructor(private readonly ordersService: OrdersService) {}

  @Post()
  create(@Body() order: CreateOrderDto) {
    return this.ordersService.create(order);
  }
}
Filterall-exceptions.filter.tsOne place decides how errors look and logs each one once. Unknown errors become a 500 without their message; the real error goes to the log with its stack.
import { type ArgumentsHost, Catch, type ExceptionFilter, HttpException, Logger } from "@nestjs/common";
import type { Response } from "express";
import { requestContext } from "./request-context.js";

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger("Errors");

  catch(exception: unknown, host: ArgumentsHost) {
    const response = host.switchToHttp().getResponse<Response>();
    const requestId = requestContext.getStore()?.requestId;

    if (exception instanceof HttpException) {
      this.logger.warn({ message: "request rejected", status: exception.getStatus(), requestId });
      return response.status(exception.getStatus()).json(exception.getResponse());
    }
    this.logger.error({ message: "request failed", requestId }, (exception as Error)?.stack);
    response.status(500).json({ statusCode: 500, message: "Internal server error", requestId });
  }
}
