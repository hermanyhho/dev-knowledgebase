JavaScript / Web

Fastify

A web framework for Node.js built to add as little work per request as possible.

What it is

Fastify is a library for building HTTP APIs in Node.js. You register routes, and Fastify calls your handler when a matching request arrives. Version 5 is current and needs Node.js 20 or newer.

Each request passes through a fixed list of steps called the lifecycle. You add code to a step with a hook. Each route can declare a JSON schema for its input and output. Fastify compiles the schema into a validation function and a serialization function when the server starts, so each request does less work.

Code is grouped into plugins. Each plugin gets its own copy of the Fastify instance, so what it adds stays inside it unless you say otherwise.

TermMeaningIn the example
HookA function that runs at one named step of the lifecycle.app.addHook("onRequest", app.authenticate)
SchemaA JSON Schema object that describes the body, params, query, headers or response of a route.createUserBodySchema
AjvThe library that turns a schema into a validation function.Rejects a body without email
fast-json-stringifyThe library that turns a response schema into a function that writes JSON.Drops passwordHash from the output
PluginAn async function that receives an instance and adds routes, hooks or decorators to it. Loaded with register.usersRoutes, authPlugin
EncapsulationA registered plugin works on a child instance. The parent cannot see what the child adds.The root has no usersRepository
DecoratorA property or function added to the instance, the request or the reply.app.decorate("authenticate", ...)
pinoThe JSON logger built into Fastify.request.log.info(...)
Main rule: give every route a schema for its input and its response. The input schema rejects bad requests before your handler runs. The response schema makes JSON output faster and sends only the fields you listed.

Request lifecycle hooks in order

Fastify runs these steps for every request, top to bottom. Hooks are optional. If a hook sends a reply or throws, the steps that build the response are skipped.

Schemas for validation and serialization

You add schemas in the route options under schema. When the server starts, Fastify compiles each one into a JavaScript function. A request then runs that function instead of reading the schema again.

PartWhat Fastify does with itWhy it is faster or safer
schema.body, params, querystring, headersAjv validates the input. Failure sends 400 with a message such as body must have required property 'email'.The handler only sees valid input, and the check is compiled code.
schema.response, per status codefast-json-stringify writes the JSON for that status code.It knows every field and type in advance, so it skips the checks JSON.stringify makes. Fields not in the schema are left out.
Fastify's Ajv settingsremoveAdditional: true, coerceTypes: "array", useDefaults: true, allErrors: falseWith additionalProperties: false, unknown fields are removed, not rejected. "42" in a query becomes 42. Only the first error is reported.
Route lookupfind-my-way, a radix tree of pathsMatching a URL does not loop over every route.

Graceful shutdown

A container platform sends SIGTERM before it stops your process. Call await app.close() when it arrives. This is what happens next:

StepWhat Fastify does
1Stops accepting new connections. New requests on open connections get 503 (return503OnClosing, on by default).
2Closes idle keep-alive connections and waits for requests in progress to finish.
3Runs onClose hooks. Close database pools here.
4Resolves the promise. Your code exits the process.

The platform kills the process after its grace period, 30 seconds by default in Kubernetes. Requests longer than that are cut off.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The client sends POST /users with a token and an x-request-id header. Fastify finds the route, sets request.id with genReqId, and logs incoming request. The onRequest hook checks the token and sets request.user.
  2. preParsing gets the raw body stream. Fastify parses the JSON into request.body. preValidation lowercases the email.
  3. The compiled Ajv function checks the body against createUserBodySchema. It passes. Unknown fields are removed.
  4. preHandler runs. The handler saves the user, logs user created with request.log, sets status 201 and returns the user object.
  5. The 201 response schema's serializer writes the JSON. passwordHash is not in the schema, so it is left out. onSend adds the x-request-id header.
  6. The response is sent. onResponse records the duration, and Fastify logs request completed with the same reqId.
  1. The client sends POST /users with a valid token but no email. Authentication, parsing and preValidation run as normal.
  2. Ajv fails: body must have required property 'email'. Fastify creates an error with statusCode 400 and skips preHandler and the handler.
  3. onError runs first and logs the error at info level, with the reqId.
  4. The error handler sees error.validation and sends status 400 with a list of the problems.
  5. The error response still goes through onSend, so it gets the x-request-id header. onResponse still runs.
  1. The client sends POST /users without an authorization header.
  2. The authenticate hook finds no token. It logs a warning and calls return reply.code(401).send(...).
  3. A reply was sent, so Fastify skips parsing, validation and the handler. The body is never read. onSend still runs.
  4. The client gets 401. onResponse records it like any other response.
  1. server.js creates the root instance with the logger and genReqId.
  2. authPlugin is wrapped in fastify-plugin, so it runs on the root. Its authenticate decorator is added to the root.
  3. register(usersRoutes) creates a child instance. The child sees authenticate from the root and adds its own usersRepository and onRequest hook.
  4. On the root, app.usersRepository is undefined. The child's hook does not run for /health either.

Problems it solves

  • Hand-written input checksA schema per route rejects bad input with 400 before your handler runs.
  • Leaking internal fieldsA response schema sends only the fields it lists.
  • Framework overhead per requestCompiled validators and serializers, and fast route lookup, leave more CPU time for your code.
  • Missing request IDs in logspino is built in, and request.log adds the reqId to every line.
  • Shared global state between modulesEncapsulation keeps each plugin's decorators and hooks to itself.

Problems it introduces

  • Schemas to maintainA field added in code but not in the response schema is silently left out.
  • Surprising Ajv defaultsUnknown fields are removed, not rejected, and query strings are coerced to numbers.
  • Encapsulation confusionA decorator or hook "missing" in another plugin is usually a scope or register-order issue.
  • Smaller ecosystem than ExpressFewer tutorials and third-party plugins. Express middleware needs an adapter.
  • Speed gains are limitedIf most time goes to the database, a faster framework changes little.

Root instancesrc/server.jsCreates the root instance with pino and genReqId, registers the shared plugins before usersRoutes, and closes the server on SIGTERM. A caller can send any x-request-id, so the pattern check keeps odd values out of the logs.
import { randomUUID } from "node:crypto";
import Fastify from "fastify";
import authPlugin from "./plugins/auth.js";
import errorHandlingPlugin from "./plugins/error-handling.js";
import requestHooksPlugin from "./plugins/request-hooks.js";
import usersRoutes from "./routes/users.js";

const safeRequestIdPattern = /^[A-Za-z0-9-]{8,64}$/;

function requestIdFromHeaderOrNew(rawRequest) {
  const incomingRequestId = rawRequest.headers["x-request-id"] ?? "";
  return safeRequestIdPattern.test(incomingRequestId) ? incomingRequestId : randomUUID();
}

const app = Fastify({
  logger: { level: process.env.LOG_LEVEL ?? "info" },
  genReqId: requestIdFromHeaderOrNew,
});

await app.register(errorHandlingPlugin);
await app.register(requestHooksPlugin);
await app.register(authPlugin);
await app.register(usersRoutes, { prefix: "/users" });

app.get("/health", async () => ({ status: "ok" }));

try {
  await app.listen({ port: Number(process.env.PORT ?? 3000), host: "0.0.0.0" });
} catch (error) {
  app.log.fatal({ err: error }, "server failed to start");
  process.exit(1);
}

for (const signal of ["SIGTERM", "SIGINT"]) {
  process.once(signal, async () => {
    app.log.info({ signal }, "signal received, closing the server");
    await app.close();
    process.exit(0);
  });
}

Shared pluginsrc/plugins/auth.jsWrapped in fastify-plugin, so authenticate is added to the root and every later plugin can use it. It is a decorator, not a global hook: each plugin chooses whether its routes need a token. Sending a reply and returning it stops the lifecycle with 401.
import fastifyPlugin from "fastify-plugin";
import { verifyAccessToken } from "../auth/tokens.js";

function bearerTokenFrom(authorizationHeader = "") {
  return authorizationHeader.startsWith("Bearer ") ? authorizationHeader.slice("Bearer ".length) : null;
}

async function authPlugin(app) {
  app.decorateRequest("user", null);

  app.decorate("authenticate", async function authenticate(request, reply) {
    const accessToken = bearerTokenFrom(request.headers.authorization);
    const user = accessToken ? await verifyAccessToken(accessToken) : null;

    if (!user) {
      request.log.warn("request rejected: access token missing or invalid");
      return reply.code(401).send({ message: "The access token is missing or invalid." });
    }

    request.user = user;
  });
}

export default fastifyPlugin(authPlugin, { name: "auth" });
Hookssrc/plugins/request-hooks.jsHooks for every route, because the plugin uses fastify-plugin. An async preParsing or onSend hook must return the payload. Fastify already logs each finished request, so onResponse records a metric instead of a second log line.
import fastifyPlugin from "fastify-plugin";
import { recordRequestDuration } from "../metrics.js";

async function requestHooksPlugin(app) {
  app.addHook("preParsing", async (request, reply, payload) => {
    request.log.debug({ contentLength: request.headers["content-length"] }, "reading request body");
    return payload;
  });

  app.addHook("preValidation", async (request) => {
    if (typeof request.body?.email === "string") {
      request.body.email = request.body.email.trim().toLowerCase();
    }
  });

  app.addHook("preHandler", async (request) => {
    request.log.debug({ userId: request.user?.id }, "input is valid, running handler");
  });

  app.addHook("onSend", async (request, reply, payload) => {
    reply.header("x-request-id", request.id);
    return payload;
  });

  app.addHook("onResponse", async (request, reply) => {
    recordRequestDuration({
      route: request.routeOptions.url,
      statusCode: reply.statusCode,
      durationMilliseconds: reply.elapsedTime,
    });
  });
}

export default fastifyPlugin(requestHooksPlugin, { name: "request-hooks" });
Errorssrc/plugins/error-handling.jsonError runs before the error handler and logs. A custom error handler replaces the default one, and the default one is what logs errors. Validation errors have error.validation. 500 responses hide the real message from the client.
import fastifyPlugin from "fastify-plugin";

async function errorHandlingPlugin(app) {
  app.addHook("onError", async (request, reply, error) => {
    const statusCode = error.statusCode ?? 500;
    if (statusCode >= 500) {
      request.log.error({ err: error }, "request failed");
    } else {
      request.log.info({ err: error }, "request rejected");
    }
  });

  app.setErrorHandler((error, request, reply) => {
    if (error.validation) {
      return reply.code(400).send({
        message: "The request is invalid.",
        problems: error.validation.map((issue) => `${error.validationContext}${issue.instancePath} ${issue.message}`),
      });
    }

    const statusCode = error.statusCode ?? 500;
    if (statusCode >= 500) {
      return reply.code(500).send({ message: "An unexpected server error occurred." });
    }
    return reply.code(statusCode).send({ message: error.message });
  });
}

export default fastifyPlugin(errorHandlingPlugin, { name: "error-handling" });
Encapsulated pluginsrc/routes/users.jsNot wrapped in fastify-plugin, so usersRepository and the onRequest hook apply only to /users routes. Handlers are async and return the body. onClose closes the database pool when app.close() runs.
import { UsersRepository } from "../data/users-repository.js";
import { createUserBodySchema, userIdParamsSchema, userResponseSchema } from "./user-schemas.js";

export default async function usersRoutes(app) {
  const usersRepository = new UsersRepository(process.env.DATABASE_URL);
  app.decorate("usersRepository", usersRepository);
  app.addHook("onClose", () => usersRepository.close());

  app.addHook("onRequest", app.authenticate);

  app.post(
    "/",
    { schema: { body: createUserBodySchema, response: { 201: userResponseSchema } } },
    async (request, reply) => {
      const createdUser = await app.usersRepository.create(request.body);
      request.log.info({ userId: createdUser.id }, "user created");
      reply.code(201);
      return createdUser;
    },
  );

  app.get(
    "/:userId",
    { schema: { params: userIdParamsSchema, response: { 200: userResponseSchema } } },
    async (request, reply) => {
      const user = await app.usersRepository.findById(request.params.userId);
      if (!user) {
        return reply.code(404).send({ message: "The user does not exist." });
      }
      return user;
    },
  );
}
