NestJS Request Lifecycle

The fixed order of steps an HTTP request passes through in NestJS, and which step to use for what. Examples use NestJS 12.

What it is

In Express, everything that runs before a route handler is middleware. NestJS splits that work into five kinds of steps, each with one job: middleware, guards, interceptors, pipes and exception filters. They always run in the same order.

Each step is a class that Nest creates with dependency injection, so a guard can use a service to check a token. Each can be attached to the whole app, one controller, one route method, or one parameter.

The order below was measured in a NestJS 12 app that recorded each step.

TermMeaningIn the example
MiddlewareA function that runs before Nest picks the route. It sees the raw request.Sets the request ID
GuardA class whose canActivate returns true or false: may this request reach the handler?RolesGuard
InterceptorA class that runs code before the handler and can change or time the result after it.RequestLogInterceptor
PipeA class that validates or converts one handler argument.ValidationPipe, ParseIntPipe
HandlerThe controller method for the route.OrdersController.create
Exception filterA class that turns a thrown exception into an HTTP response.AllExceptionsFilter
ExecutionContextAn object passed to guards and interceptors with the request, the controller class and the handler method.context.getHandler()
ObservableAn RxJS stream. An interceptor receives the handler's result as one, and can add steps to it.next.handle().pipe(tap(...))
Main rule: put each concern in its own step. Who may call: a guard. Is the input valid: a pipe. Timing and response shape for every route: an interceptor. How errors look: one global exception filter.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. An admin sends POST /orders. The middleware creates request ID r-1 and stores it in AsyncLocalStorage for the rest of the request.
  2. The guard reads the roles required by @Roles("admin") on the method and compares them with the user's roles. They match.
  3. The interceptor notes the start time and calls next.handle().
  4. ValidationPipe turns the JSON body into a CreateOrderDto and checks its rules. It passes.
  5. The handler creates the order and returns it.
  6. The result passes back through the interceptor, which logs method, route, status 201, duration and r-1. The client gets the order and the x-request-id header.
  1. A user without the admin role sends POST /orders.
  2. The guard finds no admin role and returns false.
  3. Nest throws ForbiddenException. The interceptor, pipe and handler never run. The filter answers 403 Forbidden resource and logs it at warn.
  4. Because the interceptor did not run, its log line is missing for this request. The filter's line, with the same request ID, covers it.
  1. An admin sends an order with "quantity": "two". Middleware, guard and interceptor run as usual.
  2. ValidationPipe checks the body with the rules on CreateOrderDto. @IsInt() fails.
  3. The pipe throws BadRequestException with every failed rule. The handler never runs. The filter answers 400 and logs the field names at warn.
  4. The client gets the list of messages and can show them next to the form fields.
  1. A valid request reaches the handler. The database connection fails, and the handler throws a plain Error.
  2. The interceptor's after step is skipped. The filter sees an exception that is not an HttpException, so it answers 500 Internal server error without the real message.
  3. The filter logs the error with its stack and request ID r-1 at error level. This is the only place it is logged.
  4. The response body includes r-1. A support request with that ID leads straight to the log line.
  1. A client sends GET /orders/7. Middleware and guard run.
  2. A cache interceptor finds the response for this URL in its cache.
  3. It returns the cached value without calling next.handle(). The pipe and handler do not run.
  4. The guard ran first, so a cached response is never given to a caller who may not see it. Interceptors cannot skip guards.

Problems it solves

  • Checks repeated in every handlerAuthorization and validation run before the handler, declared with one decorator.
  • Unclear order of middlewareThe order of the five steps is fixed, whatever order you register them in.
  • Different error formatsOne global filter decides how every error response looks and where it is logged.
  • Untestable cross-cutting codeGuards, pipes and interceptors are classes with injected services, testable on their own.

Problems it introduces

  • Five concepts to learnExpress has one: middleware. Choosing the right step takes practice.
  • Logic spread over decoratorsWhat happens on a route depends on decorators at app, controller and method level.
  • RxJS in interceptorsThe after step uses RxJS operators, another library to understand.
  • Steps that do not runA rejected or failed request skips later steps, so logging must not rely on all of them.
Middlewaresrc/request-context.tsThe middleware runs the rest of the request inside requestContext.run. Every later step, and every await in them, can read the ID with currentRequestId(). A client or gateway can send its own x-request-id, so one ID covers several services.
import { AsyncLocalStorage } from "node:async_hooks";
import { randomUUID } from "node:crypto";
import { Injectable, type NestMiddleware } from "@nestjs/common";
import type { NextFunction, Request, Response } from "express";

const requestContext = new AsyncLocalStorage<{ requestId: string }>();

export function currentRequestId(): string | undefined {
  return requestContext.getStore()?.requestId;
}

@Injectable()
export class RequestContextMiddleware implements NestMiddleware {
  use(req: Request, res: Response, next: NextFunction) {
    const requestId = req.header("x-request-id") ?? randomUUID();
    res.setHeader("x-request-id", requestId);
    requestContext.run({ requestId }, next);
  }
}
Setupsrc/app.module.tsThe guard, pipe, interceptor and filter are registered for the whole app as providers, so Nest creates them with injection. The middleware is registered in configure. "*path" matches every route.
import { type MiddlewareConsumer, Module, ValidationPipe } from "@nestjs/common";
import { APP_FILTER, APP_GUARD, APP_INTERCEPTOR, APP_PIPE } from "@nestjs/core";
import { AllExceptionsFilter } from "./all-exceptions.filter.js";
import { RolesGuard } from "./auth/roles.guard.js";
import { OrdersController } from "./orders/orders.controller.js";
import { RequestContextMiddleware } from "./request-context.js";
import { RequestLogInterceptor } from "./request-log.interceptor.js";

@Module({
  controllers: [OrdersController],
  providers: [
    { provide: APP_GUARD, useClass: RolesGuard },
    { provide: APP_INTERCEPTOR, useClass: RequestLogInterceptor },
    { provide: APP_PIPE, useValue: new ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true }) },
    { provide: APP_FILTER, useClass: AllExceptionsFilter },
  ],
})
export class AppModule {
  configure(consumer: MiddlewareConsumer) {
    consumer.apply(RequestContextMiddleware).forRoutes("*path");
  }
}
Guardsrc/auth/roles.guard.tsRoles is a decorator that stores a list of roles on a method. The guard reads it from the handler in the ExecutionContext. Routes without @Roles pass. req.user is set earlier by the authentication step, for example a JWT guard.
import { type CanActivate, type ExecutionContext, Injectable } from "@nestjs/common";
import { Reflector } from "@nestjs/core";

export const Roles = Reflector.createDecorator<string[]>();

@Injectable()
export class RolesGuard implements CanActivate {
  constructor(private readonly reflector: Reflector) {}

  canActivate(context: ExecutionContext): boolean {
    const requiredRoles = this.reflector.get(Roles, context.getHandler());
    if (!requiredRoles) return true;

    const user = context.switchToHttp().getRequest().user as { roles: string[] } | undefined;
    return requiredRoles.some((role) => user?.roles.includes(role));
  }
}
Interceptorsrc/request-log.interceptor.tsCode before next.handle() runs before the handler; the tap callback runs after it, with the result. This writes one line per successful request. Failed requests skip tap, so the exception filter logs those.
import { type CallHandler, type ExecutionContext, Injectable, Logger, type NestInterceptor } from "@nestjs/common";
import type { Request, Response } from "express";
import { tap } from "rxjs";
import { currentRequestId } from "./request-context.js";

@Injectable()
export class RequestLogInterceptor implements NestInterceptor {
  private readonly logger = new Logger("Request");

  intercept(context: ExecutionContext, next: CallHandler) {
    const startedAt = performance.now();
    const http = context.switchToHttp();
    const req = http.getRequest<Request>();

    return next.handle().pipe(
      tap(() => {
        this.logger.log({
          message: "request finished",
          method: req.method,
          route: req.route?.path,
          status: http.getResponse<Response>().statusCode,
          durationMs: Math.round(performance.now() - startedAt),
          requestId: currentRequestId(),
        });
      }),
    );
  }
}
Pipesrc/orders/create-order.dto.tsThe global ValidationPipe turns the body into this class and checks each decorator, using the class-validator and class-transformer packages. whitelist with forbidNonWhitelisted rejects fields the class does not declare. A failure gives 400 with one message per failed rule, such as items.0.quantity must be an integer number. Tested with NestJS 12 and class-validator.
import { Type } from "class-transformer";
import { ArrayMinSize, IsInt, IsString, Min, ValidateNested } from "class-validator";

export class OrderItemDto {
  @IsString()
  productId!: string;

  @IsInt()
  @Min(1)
  quantity!: number;
}

export class CreateOrderDto {
  @IsString()
  customerId!: string;

  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  @ArrayMinSize(1)
  items!: OrderItemDto[];
}
Handlersrc/orders/orders.controller.tsBy the time the method runs, the guard has checked the role and the pipe has checked the body. ParseIntPipe on the route parameter turns "7" into 7. Throwing NotFoundException gives a 404 through the filter.
import { Body, Controller, Get, NotFoundException, Param, ParseIntPipe, Post } from "@nestjs/common";
import { Roles } from "../auth/roles.guard.js";
import { CreateOrderDto } from "./create-order.dto.js";

@Controller("orders")
export class OrdersController {
  private readonly orders = new Map<number, CreateOrderDto>();

  @Post()
  @Roles(["admin"])
  create(@Body() order: CreateOrderDto) {
    const orderId = this.orders.size + 1;
    this.orders.set(orderId, order);
    return { orderId, ...order };
  }

  @Get(":orderId")
  findOne(@Param("orderId", ParseIntPipe) orderId: number) {
    const order = this.orders.get(orderId);
    if (!order) throw new NotFoundException(`Order ${orderId} does not exist.`);
    return order;
  }
}
Filtersrc/all-exceptions.filter.ts@Catch() with no argument catches everything. HttpExceptions keep their status and message, and are logged at warn without a stack. Anything else becomes a 500 with a fixed message, and the real error is logged at error with its stack. The request ID goes into the log and the response.
import { type ArgumentsHost, Catch, type ExceptionFilter, HttpException, Logger } from "@nestjs/common";
import type { Request, Response } from "express";
import { currentRequestId } from "./request-context.js";

@Catch()
export class AllExceptionsFilter implements ExceptionFilter {
  private readonly logger = new Logger("Errors");

  catch(exception: unknown, host: ArgumentsHost) {
    const http = host.switchToHttp();
    const req = http.getRequest<Request>();
    const requestId = currentRequestId();
    const logFields = { method: req.method, path: req.path, requestId };

    if (exception instanceof HttpException) {
      const status = exception.getStatus();
      this.logger.warn({ message: "request rejected", status, reason: exception.message, ...logFields });
      return http.getResponse<Response>().status(status).json({ ...this.bodyOf(exception), requestId });
    }

    this.logger.error({ message: "request failed", ...logFields }, (exception as Error)?.stack);
    http.getResponse<Response>().status(500).json({ statusCode: 500, message: "Internal server error", requestId });
  }

  private bodyOf(exception: HttpException) {
    const response = exception.getResponse();
    return typeof response === "string" ? { statusCode: exception.getStatus(), message: response } : response;
  }
}
