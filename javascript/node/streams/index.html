Node Streams

Data processed in small chunks as it arrives, instead of loaded into memory all at once. Module: node:stream.

What it is

A stream moves data in pieces called chunks. A file read with fs.readFile is loaded into memory whole before your code sees it. A file read with fs.createReadStream arrives 64 KiB at a time, and each chunk can be processed and dropped before the next one is read.

This keeps memory use about the same for a 5 MB file and a 5 GB file. It also lets work start before all the data has arrived: the first rows of an upload can be saved while the rest is still on the network.

Many parts of Node.js are streams. Files, HTTP requests and responses, sockets, zlib compression and process.stdout are all streams.

TermMeaningIn the example

Main rule: connect streams with await pipeline(...) from node:stream/promises. It handles backpressure, errors and cleanup for every stream in the chain.

The four stream types

TypeWhat it doesExamples in Node.js
ReadableProduces chunks. You read from it.fs.createReadStream, the HTTP request on a server (req), process.stdin, Readable.from(array)
WritableTakes chunks. You write to it.fs.createWriteStream, the HTTP response on a server (res), process.stdout
DuplexReadable and writable, with two separate directions. What you write does not come back out.A TCP socket from node:net: you send bytes and receive other bytes
TransformA Duplex whose output is computed from its input.zlib.createGzip(), crypto.createHash(), your own parser

Why pipeline() and not .pipe()

source.pipe(destination) is the older way to connect two streams. It handles backpressure, but not errors. If one stream fails, the others stay open, and the error is not passed along the chain.

Situationa.pipe(b).pipe(c)await pipeline(a, b, c)
A stream emits an errorOnly that stream's own error listeners hear it. Without one, the process crashes.The returned promise rejects. One try/catch covers every stream.
Cleanup after an errorThe other streams stay open. File handles and sockets leak.Every stream is destroyed, which closes files and sockets.
HTTP client disconnects mid-downloadThe file stream stays open. Its file handle leaks.The file stream and gzip are destroyed. The error is ERR_STREAM_PREMATURE_CLOSE.
Knowing when it finishedListen for finish on the last stream.await the promise.
Async generator stepsNot supportedSupported: pipeline(file, async function* (chunks) { ... }, output)

Backpressure step by step

A disk reads far faster than a phone downloads. Without backpressure, every chunk read waits in the writer's buffer, and memory grows until the process crashes.

StepWhat happens
1. Writewritable.write(chunk) adds the chunk to the writer's buffer.
2. Buffer fullWhen buffered data reaches highWaterMark, write() returns false. The chunk is still accepted. false means "stop sending for now".
3. PauseThe reader pauses. pipeline() does this for you. In your own loop, await once(writable, "drain").
4. DrainWhen the destination has taken the buffered data, the writer emits drain.
5. ResumeThe reader continues. Memory stays near highWaterMark for each stream in the chain.

Object mode and for await

By default a stream carries bytes, as Buffer or string chunks. With objectMode: true, each chunk is one JavaScript value, such as a parsed order. highWaterMark then counts objects, 16 by default, not bytes.

Every Readable is an async iterable. for await (const chunk of readable) reads one chunk at a time, and the stream does not read ahead further than highWaterMark while your loop body awaits. If the loop body throws, or you break, the stream is destroyed. This is often the shortest correct way to consume a stream.

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. Your code calls await pipeline(createReadStream("orders.csv"), createGzip(), createWriteStream("orders.csv.gz")).
  2. The Readable reads the first 64 KiB from disk. The other 4.99 GB stay on disk.
  3. The gzip Transform compresses the chunk. Its output is smaller than its input.
  4. The Writable buffers the compressed chunk and writes it to orders.csv.gz. The chunk is then dropped from memory.
  5. This repeats about 80 000 times. Only a few chunks are in memory at any moment, so memory use is the same for a 5 MB file and a 5 GB file.
  6. After the last chunk, every stream finishes and the promise resolves. Log the bytes read and the duration.
  1. A user downloads the export on a slow phone connection at 1 MB per second. The disk can read 500 MB per second.
  2. Chunks arrive at the Writable faster than the response can send them. They wait in its buffer.
  3. The buffer reaches highWaterMark. write() returns false: stop sending for now.
  4. pipeline() sees false and pauses the Readable. No more file reads happen.
  5. The phone takes the buffered data. The buffer is empty, so the Writable emits drain.
  6. pipeline() resumes the Readable. The download runs at the phone's speed, and memory stays near highWaterMark per stream.
  1. An import reads orders.csv, splits it into lines, and parses each line into an order object in object mode.
  2. The Writable inserts rows into the database in batches of 500. 48 000 rows are saved.
  3. Row 48 213 has an empty date. The Transform calls its callback with an InvalidOrderRowError that holds the row number.
  4. pipeline() destroys all streams. The file handle closes and the buffered rows are dropped. With .pipe(), the file would stay open.
  5. The promise rejects. Your catch logs the error, row 48 213, the rows already inserted and the request ID. Those 48 000 rows stay in the table unless the import uses a transaction or a staging table.
  1. Your code calls await readFile("orders.csv", "utf8") on a 200 MB file. Nothing runs until the whole file is in memory.
  2. Memory holds the 200 MB buffer, then the decoded string, then split("\n") creates millions of small strings. Memory use is several times the file size.
  3. Ten users start an import at the same time. Ten copies are in memory, and the container is killed for going over its memory limit.
  4. With the 5 GB file, readFile fails at once with ERR_FS_FILE_TOO_LARGE: its limit is 2 GiB.
  5. The fix is a stream: memory stays near highWaterMark per stream, whatever the file size. See the first flow.

order-import/

Problems it solves

  • Memory grows with file sizeA stream holds a few chunks at a time, so a 5 GB file needs about as much memory as a 5 MB one.
  • Waiting for all data before startingThe first rows are processed while the rest is still being read or uploaded.
  • Fast producers and slow consumersBackpressure pauses the reader until the writer has room again.
  • Reusable stepsGzip, hashing and parsing are separate Transforms that fit into any chain.
  • Files over 2 GiBreadFile refuses them. Streams have no size limit.

Problems it introduces

  • More code than readFileFor small files, such as config, readFile is shorter and fine.
  • Partial results after an errorRows written before the failure stay written. Plan for a transaction, a staging table or a restart point.
  • Data split across chunksA line, a multi-byte character or a JSON value can be cut between two chunks. Your Transform must handle it.
  • Leaks with .pipe()Errors are not passed on and streams are not closed. Use pipeline().
  • Two stream APIsNode.js streams and web streams differ. Convert with Readable.fromWeb and Readable.toWeb.
pipeline()src/import-orders.jsConnects the file, the line splitter, the row parser and the database writer. Logs progress every 10 seconds, and on failure logs how many rows were saved. The request handler logs the error itself once, with the row number. One try/catch covers all four steps.
import { pipeline } from "node:stream/promises";
import pg from "pg";
import pino from "pino";
import { openOrdersFile, splitIntoLines } from "./csv-lines.js";
import { OrderRowParser } from "./order-row-parser.js";
import { OrderDatabaseWriter } from "./order-database-writer.js";

const logger = pino();
const database = new pg.Pool();

export async function importOrders(filePath, requestId) {
  const importLogger = logger.child({ requestId, filePath });
  const ordersFile = openOrdersFile(filePath);
  const databaseWriter = new OrderDatabaseWriter(database);
  const startedAt = Date.now();
  const progress = () => ({ bytesRead: ordersFile.bytesRead, rowsInserted: databaseWriter.rowsInserted });

  importLogger.info("order import started");
  const progressTimer = setInterval(() => importLogger.info(progress(), "order import progress"), 10_000);

  try {
    await pipeline(ordersFile, splitIntoLines, new OrderRowParser(), databaseWriter);
    importLogger.info({ ...progress(), durationMs: Date.now() - startedAt }, "order import finished");
  } catch (error) {
    importLogger.info(progress(), "order import stopped");
    throw error;
  } finally {
    clearInterval(progressTimer);
  }
}
Readablesrc/csv-lines.jsThe file stream reads 64 KiB at a time. encoding: "utf8" makes it return strings and keeps characters that are split between two chunks intact. splitIntoLines is an async generator: for await reads one chunk, and a line cut off at the end of a chunk is kept until the next chunk arrives. pipeline() accepts it as a step.
import { createReadStream } from "node:fs";

export function openOrdersFile(filePath) {
  return createReadStream(filePath, { encoding: "utf8", highWaterMark: 64 * 1024 });
}

export async function* splitIntoLines(textChunks) {
  let unfinishedLine = "";
  for await (const textChunk of textChunks) {
    const lines = (unfinishedLine + textChunk).split("\n");
    unfinishedLine = lines.pop();
    yield* lines;
  }
  if (unfinishedLine !== "") yield unfinishedLine;
}

export async function countOrderRows(filePath) {
  let lineCount = 0;
  for await (const line of splitIntoLines(openOrdersFile(filePath))) {
    if (line.trim() !== "") lineCount += 1;
  }
  return lineCount - 1;
}
Transformsrc/order-row-parser.jsA Transform in object mode: a line string goes in, an order object comes out. A bad row is passed to callback as an error with its row number, so pipeline() stops and the log says which row failed. This parser splits on commas only. Real CSV with quoted fields needs a parser such as csv-parse.
import { Transform } from "node:stream";

export class InvalidOrderRowError extends Error {
  constructor(rowNumber, line) {
    super(`Order row ${rowNumber} is invalid.`);
    this.rowNumber = rowNumber;
    this.line = line;
  }
}

export class OrderRowParser extends Transform {
  #rowNumber = 0;

  constructor() {
    super({ objectMode: true });
  }

  _transform(line, encoding, callback) {
    this.#rowNumber += 1;
    const isHeaderRow = this.#rowNumber === 1;
    if (isHeaderRow || line.trim() === "") return callback();

    const [orderId, customerId, totalText, orderedAtText] = line.trimEnd().split(",");
    const total = Number(totalText);
    const orderedAt = new Date(orderedAtText);

    if (!orderId || Number.isNaN(total) || Number.isNaN(orderedAt.getTime())) {
      return callback(new InvalidOrderRowError(this.#rowNumber, line));
    }
    callback(null, { orderId, customerId, total, orderedAt });
  }
}
Writablesrc/order-database-writer.jsA Writable in object mode that collects 500 orders, then inserts them in one query. It calls callback only after the insert, so the stream does not take more rows while the database is busy: that is backpressure. _final inserts the last, smaller batch.
import { Writable } from "node:stream";

const rowsPerInsert = 500;

export class OrderDatabaseWriter extends Writable {
  #database;
  #pendingOrders = [];
  rowsInserted = 0;

  constructor(database) {
    super({ objectMode: true });
    this.#database = database;
  }

  _write(order, encoding, callback) {
    this.#pendingOrders.push(order);
    if (this.#pendingOrders.length < rowsPerInsert) return callback();
    this.#insertPendingOrders().then(() => callback(), callback);
  }

  _final(callback) {
    this.#insertPendingOrders().then(() => callback(), callback);
  }

  async #insertPendingOrders() {
    if (this.#pendingOrders.length === 0) return;
    const orders = this.#pendingOrders;
    this.#pendingOrders = [];

    await this.#database.query(
      `INSERT INTO orders (order_id, customer_id, total, ordered_at)
       SELECT * FROM unnest($1::text[], $2::text[], $3::numeric[], $4::timestamptz[])`,
      [
        orders.map((order) => order.orderId),
        orders.map((order) => order.customerId),
        orders.map((order) => order.total),
        orders.map((order) => order.orderedAt),
      ],
    );
    this.rowsInserted += orders.length;
  }
}
HTTPsrc/server.jsOn a server, req is a Readable and res is a Writable. The upload goes to disk without being held in memory. The download is gzipped on the way out. If the client disconnects, pipeline() closes the file and logs a warning, because the client chose to leave.
import http from "node:http";
import { createReadStream, createWriteStream } from "node:fs";
import { pipeline } from "node:stream/promises";
import { createGzip } from "node:zlib";
import { randomUUID } from "node:crypto";
import pino from "pino";
import { importOrders } from "./import-orders.js";

const logger = pino();
const exportFilePath = "/data/exports/orders.csv";

async function receiveUpload(req, res, requestLogger, requestId) {
  const uploadPath = `/data/uploads/${requestId}.csv`;
  await pipeline(req, createWriteStream(uploadPath));
  requestLogger.info({ uploadPath }, "upload saved");
  await importOrders(uploadPath, requestId);
  res.statusCode = 201;
  res.end();
}

async function sendExport(req, res, requestLogger) {
  const exportFile = createReadStream(exportFilePath);
  res.writeHead(200, { "Content-Type": "text/csv", "Content-Encoding": "gzip" });
  try {
    await pipeline(exportFile, createGzip(), res);
    requestLogger.info({ bytesRead: exportFile.bytesRead }, "export sent");
  } catch (error) {
    requestLogger.warn({ err: error, bytesRead: exportFile.bytesRead }, "export stopped before the end");
  }
}

http
  .createServer(async (req, res) => {
    const requestId = req.headers["x-request-id"] ?? randomUUID();
    const requestLogger = logger.child({ requestId, method: req.method, url: req.url });
    try {
      if (req.method === "PUT" && req.url === "/imports/orders") return await receiveUpload(req, res, requestLogger, requestId);
      if (req.method === "GET" && req.url === "/exports/orders") return await sendExport(req, res, requestLogger);
      res.statusCode = 404;
      res.end();
    } catch (error) {
      requestLogger.error({ err: error, rowNumber: error.rowNumber }, "request failed");
      if (!res.headersSent) res.statusCode = error.rowNumber ? 422 : 500;
      res.end();
    }
  })
  .listen(3000);

Backpressureexamples/backpressure.jsWrites 5 million lines by hand, without pipeline(). When write() returns false, the loop waits for drain. Remove the await once(...) and all 5 million lines wait in the stream's buffer, and memory grows to hundreds of MB.
import { createWriteStream } from "node:fs";
import { once } from "node:events";

const logFile = createWriteStream("five-million-lines.txt");
let drainWaits = 0;

for (let lineNumber = 1; lineNumber <= 5_000_000; lineNumber++) {
  const bufferHasRoom = logFile.write(`line ${lineNumber}\n`);
  if (!bufferHasRoom) {
    drainWaits += 1;
    await once(logFile, "drain");
  }
}

logFile.end();
await once(logFile, "finish");

console.log({
  highWaterMark: logFile.writableHighWaterMark,
  drainWaits,
  memoryMegabytes: Math.round(process.memoryUsage().rss / 1024 / 1024),
});
