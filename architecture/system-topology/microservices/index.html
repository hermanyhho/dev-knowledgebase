Architecture / System topology

Microservices

Also called a microservice architecture. Named and described by James Lewis and Martin Fowler in 2014.

What it is

An application split into small, separate apps called services. Each service covers one business area, runs in its own process, is deployed on its own and owns its own database.

Services talk over the network. When the caller needs an answer now, it sends a request, for example over HTTP. When it does not need to wait, it publishes a message to a message broker, and other services read it later.

This page uses the same shop as the monolith page. There, Orders, Users, Payments and Notifications were modules in one process. Here, each one is its own service.

TermMeaningIn the example
ServiceA separate app for one business area, with its own deploy and its own data.Order service, User service
API gatewayThe one public address. It sends each request to the service that handles it.nginx routing /orders
Synchronous callA request where the caller waits for the answer.Order service asks User service for the customer
Message brokerA server that stores messages in queues until a service reads them.RabbitMQ
EventA message that says something happened. The sender does not wait for anyone to read it.OrderPlaced
Database per serviceEach service has its own database. No other service reads it.Orders DB, Users DB, Payments DB
Eventual consistencyData in different services matches after a short delay, not at the same moment.The email is sent after the order is saved
The one rule: each service owns its data. Other services never read its database. They call its API or listen to its events.

Diagram

Example flow: POST /orders

Press Play to follow one request through the diagram, step by step.

  1. The gateway sends POST /orders to one of the 3 copies of the order service.
  2. The order service asks the user service for the customer over HTTP and waits. The user service reads its own database.
  3. The order service asks the payment service to charge the card and waits. The payment service calls Stripe and saves the payment in its own database.
  4. The order service saves the order in its own database. No transaction covers both the payment and the order, because they are in different databases.
  5. The order service publishes an OrderPlaced event to RabbitMQ and returns 201. It does not wait for the email.
  6. The notification service reads the event and sends the email. If it was down, the event waits in the queue until it starts again.

Problems it solves

  • Every change redeploys everythingA fix in the notification service deploys only that service. The others keep running.
  • Scaling is all or nothingRun 3 copies of the busy order service and 1 copy of the user service.
  • One fault stops every featureIf the notification service is down, orders still go through. The events wait in the queue.
  • Large teams wait on each otherEach team owns one service: its code, database and release schedule.
  • One tech stack for allEach service can use its own language, framework version or database type.
  • Large codebaseEach service is small enough to read, build and test quickly.

Problems it introduces

  • Network calls can failEvery call between services needs timeouts, retries and handling for when the other service is down.
  • No transaction across servicesIf the order insert fails after the payment is saved, the payment must be refunded with extra code. Patterns such as saga and outbox handle this.
  • Data is split upNo joins or foreign keys across services. A report that needs orders and users must copy data into one place.
  • Harder debuggingOne request runs in several processes. You need a shared request ID and distributed tracing to follow it.
  • Much more to runA gateway, a broker, several databases, and a build, deploy and monitoring setup for each service.
  • Changes to contracts need coordinationChanging OrderPlaced or an API breaks the services that use it, unless you add a new version next to the old one.

Serviceorder-service/src/orderRoutes.tsCalls two services over HTTP and checks each answer, because either call can fail. Then saves to its own database and publishes an event.
import { randomUUID } from "node:crypto";
import { Router } from "express";
import { Pool } from "pg";
import { Channel } from "amqplib";
import { OrderPlaced } from "../../contracts/OrderPlaced";

type OrderItem = { productId: string; price: number; quantity: number };

export function orderRoutes(db: Pool, events: Channel): Router {
  const router = Router();

  router.post("/orders", async (req, res) => {
    const { userId, paymentMethodId } = req.body;
    const items: OrderItem[] = req.body.items;

    const userResponse = await fetch(`${process.env.USER_SERVICE_URL}/users/${userId}`);
    if (!userResponse.ok) {
      return res.status(422).json({ error: "The user does not exist." });
    }
    const user = await userResponse.json();

    const orderId = randomUUID();
    const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);

    const paymentResponse = await fetch(`${process.env.PAYMENT_SERVICE_URL}/payments`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ orderId, amount: total, paymentMethodId }),
    });
    if (!paymentResponse.ok) {
      return res.status(502).json({ error: "The payment failed." });
    }

    await db.query("INSERT INTO orders (id, user_id, total) VALUES ($1, $2, $3)", [orderId, userId, total]);

    const event: OrderPlaced = { orderId, userId, email: user.email, total };
    events.publish("orders", "order.placed", Buffer.from(JSON.stringify(event)));

    res.status(201).json({ orderId });
  });

  return router;
}
Serviceuser-service/src/userRoutes.tsOther services get user data through this endpoint, never from the users table.
import { Router } from "express";
import { Pool } from "pg";

export function userRoutes(db: Pool): Router {
  const router = Router();

  router.get("/users/:id", async (req, res) => {
    const result = await db.query("SELECT id, email FROM users WHERE id = $1", [req.params.id]);
    if (result.rowCount === 0) {
      return res.status(404).json({ error: "The user does not exist." });
    }
    res.json(result.rows[0]);
  });

  return router;
}
Servicepayment-service/src/paymentRoutes.tsCharges the card through Stripe and saves the payment in its own database.
import { randomUUID } from "node:crypto";
import { Router } from "express";
import { Pool } from "pg";
import Stripe from "stripe";

export function paymentRoutes(db: Pool, stripe: Stripe): Router {
  const router = Router();

  router.post("/payments", async (req, res) => {
    const { orderId, amount, paymentMethodId } = req.body;

    const paymentIntent = await stripe.paymentIntents.create({
      amount: Math.round(amount * 100),
      currency: "eur",
      payment_method: paymentMethodId,
      confirm: true,
    });

    await db.query(
      "INSERT INTO payments (id, order_id, amount, provider_id) VALUES ($1, $2, $3, $4)",
      [randomUUID(), orderId, amount, paymentIntent.id],
    );

    res.status(201).json({ providerId: paymentIntent.id });
  });

  return router;
}
Servicenotification-service/src/orderPlacedConsumer.tsReads OrderPlaced events from its own queue. A message is removed from the queue only after ack, so a crash before that means it is read again.
import { Channel } from "amqplib";
import { Transporter } from "nodemailer";
import { OrderPlaced } from "../../contracts/OrderPlaced";

const queueName = "notifications.order-placed";

export async function consumeOrderPlaced(events: Channel, mailer: Transporter): Promise<void> {
  await events.assertQueue(queueName);
  await events.bindQueue(queueName, "orders", "order.placed");

  await events.consume(queueName, async (message) => {
    if (!message) return;
    const event: OrderPlaced = JSON.parse(message.content.toString());

    await mailer.sendMail({
      from: "shop@example.com",
      to: event.email,
      subject: "Order received",
      text: `Your order ${event.orderId} has been received.`,
    });

    events.ack(message);
  });
}

Serviceorder-service/OrderEndpoints.csCalls two services over HTTP and checks each answer, because either call can fail. Then saves to its own database and publishes an event through MassTransit.
using Contracts;
using Dapper;
using MassTransit;
using Npgsql;

namespace OrderService;

public record OrderItem(string ProductId, decimal Price, int Quantity);
public record PlaceOrderRequest(Guid UserId, List<OrderItem> Items, string PaymentMethodId);
public record UserResponse(Guid Id, string Email);

public static class OrderEndpoints
{
    public static void MapOrderEndpoints(this WebApplication app)
    {
        app.MapPost("/orders", async (
            PlaceOrderRequest request,
            IHttpClientFactory httpClients,
            NpgsqlDataSource db,
            IPublishEndpoint events) =>
        {
            var userResponse = await httpClients.CreateClient("user-service").GetAsync($"/users/{request.UserId}");
            if (!userResponse.IsSuccessStatusCode)
                return Results.UnprocessableEntity(new { error = "The user does not exist." });
            var user = await userResponse.Content.ReadFromJsonAsync<UserResponse>();

            var orderId = Guid.NewGuid();
            var total = request.Items.Sum(item => item.Price * item.Quantity);

            var paymentResponse = await httpClients.CreateClient("payment-service")
                .PostAsJsonAsync("/payments", new { orderId, amount = total, request.PaymentMethodId });
            if (!paymentResponse.IsSuccessStatusCode)
                return Results.Json(new { error = "The payment failed." }, statusCode: 502);

            await using var connection = await db.OpenConnectionAsync();
            await connection.ExecuteAsync(
                "INSERT INTO orders (id, user_id, total) VALUES (@orderId, @userId, @total)",
                new { orderId, userId = request.UserId, total });

            await events.Publish(new OrderPlaced(orderId, request.UserId, user!.Email, total));

            return Results.Created($"/orders/{orderId}", new { orderId });
        });
    }
}
Serviceuser-service/UserEndpoints.csOther services get user data through this endpoint, never from the users table.
using Dapper;
using Npgsql;

namespace UserService;

public record User(Guid Id, string Email);

public static class UserEndpoints
{
    public static void MapUserEndpoints(this WebApplication app)
    {
        app.MapGet("/users/{id:guid}", async (Guid id, NpgsqlDataSource db) =>
        {
            await using var connection = await db.OpenConnectionAsync();
            var user = await connection.QuerySingleOrDefaultAsync<User>(
                "SELECT id, email FROM users WHERE id = @id", new { id });

            return user is null
                ? Results.NotFound(new { error = "The user does not exist." })
                : Results.Ok(user);
        });
    }
}
Servicepayment-service/PaymentEndpoints.csCharges the card through Stripe and saves the payment in its own database.
using Dapper;
using Npgsql;
using Stripe;

namespace PaymentService;

public record PaymentRequest(Guid OrderId, decimal Amount, string PaymentMethodId);

public static class PaymentEndpoints
{
    public static void MapPaymentEndpoints(this WebApplication app)
    {
        app.MapPost("/payments", async (PaymentRequest request, PaymentIntentService stripePayments, NpgsqlDataSource db) =>
        {
            var paymentIntent = await stripePayments.CreateAsync(new PaymentIntentCreateOptions
            {
                Amount = (long)Math.Round(request.Amount * 100),
                Currency = "eur",
                PaymentMethod = request.PaymentMethodId,
                Confirm = true,
            });

            await using var connection = await db.OpenConnectionAsync();
            await connection.ExecuteAsync(
                "INSERT INTO payments (id, order_id, amount, provider_id) VALUES (@id, @orderId, @amount, @providerId)",
                new { id = Guid.NewGuid(), orderId = request.OrderId, amount = request.Amount, providerId = paymentIntent.Id });

            return Results.Created($"/payments/{paymentIntent.Id}", new { providerId = paymentIntent.Id });
        });
    }
}
