Architecture / System topology

Modular Monolith

Also called a modulith. One deployable app, split into modules with boundaries the build checks.

What it is

A monolith where each module has a public API and private internal code. Other modules may only use the public API. The compiler, a lint rule or a test fails the build when code breaks that rule.

It is still one app, built and deployed as one unit, with one database. Each module keeps its tables in its own database schema.

Modules talk through function calls to public APIs, and through an event bus that runs in the same process. Because the boundaries already exist, a module can later move out into its own service, as on the microservices page. The modules often match the bounded contexts of domain-driven design.

TermMeaningIn the example
ModuleOne business area inside the app, with its own code and its own tables.Orders, Users, Payments, Notifications
Public APIThe functions and types a module lets other modules use.UsersApi.getCustomer
Internal codeEverything else in the module. Other modules cannot import it.UserRepository
Boundary checkA rule the build enforces, so a shortcut into another module's internal code fails.Lint rule in TypeScript, internal in C#
Schema per moduleOne database, but each module's tables live in their own schema, with no foreign keys between schemas.orders.orders, users.users
In-process event busPasses events from one module to another by calling handlers directly, in the same process.OrderPlaced to Notifications
Main rule: a module uses another module only through its public API or its events. It never imports another module's internal code or reads its tables.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The HTTP route calls placeOrder on the Orders public API.
  2. The public API passes the call to OrderService, which is internal to the Orders module.
  3. OrderService calls users.getCustomer. It is a function call in the same process, but it goes through the Users public API.
  4. It calls payments.charge the same way. Payments charges the card through Stripe and saves the payment in its own schema.
  5. OrderService saves the order in the orders schema. Each module writes only to its own schema.
  6. It publishes OrderPlaced on the event bus. The bus calls the Notifications handler directly, in the same process, and the handler sends the email.
  1. A developer adds a shortcut: OrderService imports UserRepository from the Users module's internal code to run its own query.
  2. The build fails. In TypeScript, a lint rule rejects imports from another module's internal folder. In C#, UserRepository is internal, so code in the Orders project cannot see it.
  3. The fix is to call the Users public API, or to add a method to it. The Users module decides what it shares.
  1. Notifications now needs to scale on its own. It already gets its data only from OrderPlaced, and calls no other module.
  2. Replace the in-process event bus with one that sends OrderPlaced to a message broker such as RabbitMQ. OrderService does not change: it still calls bus.publish.
  3. Deploy Notifications as its own service that reads OrderPlaced from a queue. The rest of the app stays one deploy.

Problems it solves

  • Modules mixed together over timeA shortcut into another module's internal code fails the build, so boundaries stay in place.
  • The cost of microservices too earlyOne deploy, no network calls between modules, no message broker to run.
  • Not knowing what a module offersIts public API file lists everything other modules may use.
  • A later split being too hardA module with its own schema, a public API and events can move into its own service with few changes.
  • Teams changing each other's codeEach team owns its modules. Changes to a public API are visible and reviewed.
  • Hard debugging across modulesIt is still one process, so one stack trace shows the whole request.

Problems it introduces

  • Still one deployA change in any module redeploys the whole app, and you cannot scale one module on its own.
  • One fault can still stop everythingAll modules run in the same process, so a crash in one stops all of them.
  • Boundary checks need upkeepLint rules and project references must be kept up to date. A shared folder can slowly fill with code that belongs in a module.
  • More code than a plain monolithPublic API types, module setup code and an event bus, for calls that could be direct.
  • No joins across modulesA report that needs orders and customers must call both public APIs, or keep a read copy of the data.
  • In-process events are not storedIf the app stops after the order is saved but before the handler runs, the email is never sent. A slow handler also slows the request.

import { Router } from "express";
import { OrdersApi } from "../modules/orders";

export function routes(orders: OrdersApi): Router {
  const router = Router();

  router.post("/orders", async (req, res) => {
    const { customerId, items, paymentMethodId } = req.body;
    const orderId = await orders.placeOrder(customerId, items, paymentMethodId);
    res.status(201).json({ orderId });
  });

  return router;

Event bussrc/shared/eventBus.tspublish calls each handler directly, in the same process, before it returns. To move a module out later, you replace this class with one that sends events to a message broker.
type EventHandler = (event: any) => Promise<void>;

export class EventBus {
  private readonly handlersByType = new Map<string, EventHandler[]>();

  subscribe(eventType: string, handler: EventHandler): void {
    const handlers = this.handlersByType.get(eventType) ?? [];
    this.handlersByType.set(eventType, [...handlers, handler]);
  }

  async publish(event: { type: string }): Promise<void> {
    for (const handler of this.handlersByType.get(event.type) ?? []) {
      await handler(event);
    }
  }
}

Internalsrc/modules/orders/internal/OrderService.tsImports Users and Payments only through their index.ts, which the lint rule allows. Writes only to the orders schema, and tells other modules what happened through the event bus.
import { randomUUID } from "node:crypto";
import { Pool } from "pg";
import { EventBus } from "../../../shared/eventBus";
import { UsersApi } from "../../users";
import { PaymentsApi } from "../../payments";
import type { OrderPlaced } from "..";

export type OrderItem = { productId: string; price: number; quantity: number };

export class OrderService {
  constructor(
    private readonly db: Pool,
    private readonly bus: EventBus,
    private readonly users: UsersApi,
    private readonly payments: PaymentsApi,
  ) {}

  async placeOrder(customerId: string, items: OrderItem[], paymentMethodId: string): Promise<string> {
    const customer = await this.users.getCustomer(customerId);
    if (!customer) throw new Error("The customer does not exist.");

    const orderId = randomUUID();
    const total = items.reduce((sum, item) => sum + item.price * item.quantity, 0);
    await this.payments.charge(orderId, Math.round(total * 100), paymentMethodId);

    await this.db.query(
      "INSERT INTO orders.orders (id, customer_id, total) VALUES ($1, $2, $3)",
      [orderId, customerId, total],
    );

    const event: OrderPlaced = { type: "OrderPlaced", orderId, customerEmail: customer.email, total };
    await this.bus.publish(event);
    return orderId;
  }
}

Internalsrc/modules/payments/internal/PaymentService.tsCalls Stripe and writes only to the payments schema.
import { randomUUID } from "node:crypto";
import { Pool } from "pg";
import Stripe from "stripe";

export class PaymentService {
  constructor(
    private readonly db: Pool,
    private readonly stripe: Stripe,
  ) {}

  async charge(orderId: string, amountCents: number, paymentMethodId: string): Promise<string> {
    const paymentIntent = await this.stripe.paymentIntents.create({
      amount: amountCents,
      currency: "eur",
      payment_method: paymentMethodId,
      confirm: true,
    });

    await this.db.query(
      "INSERT INTO payments.payments (id, order_id, amount, provider_id) VALUES ($1, $2, $3, $4)",
      [randomUUID(), orderId, amountCents / 100, paymentIntent.id],
    );
    return paymentIntent.id;
  }
}

Event bussrc/Shop.SharedKernel/EventBus.csPublishAsync finds every registered handler for the event type and calls it directly, in the same process. To move a module out later, you replace this with a publisher that sends to a message broker.
using Microsoft.Extensions.DependencyInjection;

namespace Shop.SharedKernel;

public interface IEventHandler<in TEvent>
{
    Task HandleAsync(TEvent publishedEvent);
}

public class EventBus(IServiceProvider services)
{
    public async Task PublishAsync<TEvent>(TEvent publishedEvent)
    {
        foreach (var handler in services.GetServices<IEventHandler<TEvent>>())
            await handler.HandleAsync(publishedEvent);
    }
}

Internalsrc/Shop.Orders/Internal/OrderService.csUses Users and Payments only through IUsersModule and IPaymentsModule. Writes only to the orders schema, and tells other modules what happened through the event bus.
using Dapper;
using Npgsql;
using Shop.Payments;
using Shop.SharedKernel;
using Shop.Users;

namespace Shop.Orders.Internal;

internal sealed class OrderService(
    NpgsqlDataSource db,
    EventBus bus,
    IUsersModule users,
    IPaymentsModule payments) : IOrdersModule
{
    public async Task<Guid> PlaceOrderAsync(Guid customerId, IReadOnlyList<OrderItem> items, string paymentMethodId)
    {
        var customer = await users.GetCustomerAsync(customerId)
            ?? throw new InvalidOperationException("The customer does not exist.");

        var orderId = Guid.NewGuid();
        var total = items.Sum(item => item.Price * item.Quantity);
        await payments.ChargeAsync(orderId, (long)Math.Round(total * 100), paymentMethodId);

        await using var connection = await db.OpenConnectionAsync();
        await connection.ExecuteAsync(
            "INSERT INTO orders.orders (id, customer_id, total) VALUES (@orderId, @customerId, @total)",
            new { orderId, customerId, total });

        await bus.PublishAsync(new OrderPlaced(orderId, customer.Email, total));
        return orderId;
    }
}

using Dapper;
using Npgsql;
using Stripe;

namespace Shop.Payments.Internal;

internal sealed class PaymentService(PaymentIntentService stripePayments, NpgsqlDataSource db) : IPaymentsModule
{
    public async Task<string> ChargeAsync(Guid orderId, long amountCents, string paymentMethodId)
    {
        var paymentIntent = await stripePayments.CreateAsync(new PaymentIntentCreateOptions
        {
            Amount = amountCents,
            Currency = "eur",

            Confirm = true,

        await connection.ExecuteAsync(
            "INSERT INTO payments.payments (id, order_id, amount, provider_id) VALUES (@id, @orderId, @amount, @providerId)",
            new { id = Guid.NewGuid(), orderId, amount = amountCents / 100m, providerId = paymentIntent.Id });

        return paymentIntent.Id;
    }
}
