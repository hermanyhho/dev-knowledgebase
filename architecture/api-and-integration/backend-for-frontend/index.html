Architecture / API and integration

Backend for Frontend

Usually shortened to BFF. Described by Sam Newman in 2015, based on work at SoundCloud.

What it is

A small backend built for one frontend only. The web app gets its own BFF, and the mobile app gets another. Each BFF calls the services behind it, combines the replies and returns data in the exact shape its screens need.

The team that builds the frontend usually owns its BFF. When a screen needs a new field, that team adds it to the BFF without waiting for another team.

A BFF is often used with microservices. An API gateway gives every client the same entry point. A BFF gives each kind of client its own.

TermMeaningIn the example
FrontendThe app the user sees and touches.Web app, mobile app

Main rule: a BFF shapes data for its frontend. Business rules stay in the services, so the web and mobile apps never disagree.

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The web app sends one GraphQL query to POST /graphql on the web BFF. The query lists the fields the order page needs.
  2. The order resolver runs first. It asks the order service for the order, which holds the customer ID.
  3. The query also asks for customer, payment and recommendations. Their 3 resolvers run at the same time, one service call each.
  4. GraphQL keeps only the fields in the query. If recommendations fail, that resolver returns an empty list and the page still loads.
  5. The web app gets one JSON reply with the same shape as its query.
  1. The order history page shows one small row per order. Its query asks only for number, placedAt and total.
  2. All three fields come from the order service, so only the order resolver runs.
  3. The user, payment and recommendation services are never called. The web team built this page with a new query, without changing the BFF.
  1. The mobile app sends GET /bff/orders/42 to the mobile BFF. This REST endpoint exists for the order card screen.
  2. The mobile BFF calls only the order and payment services, at the same time. The small order card does not show the customer or recommendations.
  3. It keeps 5 small fields and turns the payment status succeeded into the display text Paid.
  4. The app gets a reply of a few hundred bytes instead of several kilobytes, which matters on a slow mobile network.
  1. Without a BFF, the mobile app calls each service itself: 3 requests over a slow mobile network. Each service must also be open to the internet.
  2. Each service returns all its data. The app downloads fields it never shows, such as warehouse IDs and card expiry dates.
  3. The app holds the code that combines the data. A change needs a new app release, and old app versions stay in use for months.

Why the web BFF uses GraphQL and the mobile BFF uses REST

Each BFF serves only one frontend, so each team picks the API style that suits its app. No other client depends on that choice. Here the web BFF uses GraphQL and the mobile BFF uses REST.

Web BFF: GraphQLMobile BFF: REST
What the app needsMany pages, each with a different mix of fields. Pages change often.A few fixed screens. One endpoint per screen is enough.
Adding a screenWrite a new query in the web app. The BFF does not change.Add or change an endpoint in the mobile BFF.
Services calledOnly those whose fields the query asks for.The ones the endpoint code calls, every time.
CachingHarder. Every request is a POST /graphql with a different body.Easy. GET /bff/orders/42 can be cached by its URL.
Old app versionsNot a concern. The browser always loads the latest web app.Old apps call the same endpoints for months, so endpoints must stay stable.
Client codeA query string, often with a library such as Apollo Client.Plain fetch.

Using one GraphQL API instead of BFFs

A common alternative is one GraphQL API for every client. Each client asks for its own fields, which solves over-fetching.

It does not give each team its own place for screen logic, such as turning succeeded into Paid for mobile only. Every team also has to agree on one shared schema, so teams wait on each other again.

Problems it solves

  • Chatty clientsOne request per screen instead of one per service. This matters most on mobile networks.
  • Over-fetchingEach frontend gets only the fields it shows. Smaller replies load faster and use less mobile data.
  • Display logic tied to app releasesCombining and formatting data happens in the BFF. Changing it does not need a new app store release.
  • One API shared by different frontendsWeb and mobile need different data and different API styles. Each BFF serves one frontend, so the web BFF uses GraphQL and the mobile BFF uses REST.
  • Services open to the internetOnly the BFFs are public. The services stay on the private network.
  • Frontend teams waiting on backend teamsThe frontend team owns its BFF and adds fields when a screen needs them.

Problems it introduces

  • More apps to runEach frontend adds a backend to build, deploy and monitor.
  • Duplicated codeEach BFF repeats the same HTTP helpers, timeouts, error handling and login checks.
  • Business rules move into the BFFIf a discount rule is coded in the web BFF only, the web and mobile apps show different prices.
  • Extra network hopEvery request goes client, then BFF, then service. The slowest service call sets the reply time.
  • Partial failuresThe BFF must decide what to return when one of its services fails or is slow.
  • How many BFFsOne per platform, or one per app? Too many BFFs repeat the same work.
Frontendweb-app/src/OrderPage.tsxA React page. Its GraphQL query lists exactly the fields the page shows, and the reply has the same shape as the query.
import { useEffect, useState } from "react";

const ORDER_PAGE_QUERY = `
  query OrderPage($id: String!) {
    order(id: $id) {
      number
      total
      items { name quantity price }
      customer { name }
      payment { cardLast4 }
      recommendations { productId name }
    }
  }
`;

type OrderPageData = {
  number: string;
  total: number;
  items: { name: string; quantity: number; price: number }[];
  customer: { name: string };
  payment: { cardLast4: string };
  recommendations: { productId: string; name: string }[];
};

export function OrderPage({ orderId }: { orderId: string }) {
  const [order, setOrder] = useState<OrderPageData | null>(null);

  useEffect(() => {
    fetch("/graphql", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      credentials: "include",
      body: JSON.stringify({ query: ORDER_PAGE_QUERY, variables: { id: orderId } }),
    })
      .then((response) => response.json())
      .then((result) => setOrder(result.data.order));
  }, [orderId]);

  if (!order) return <p>Loading order...</p>;

  return (
    <article>
      <h1>Order {order.number}</h1>
      <ul>
        {order.items.map((item) => (
          <li key={item.name}>{item.quantity} x {item.name}: {item.price} EUR</li>
        ))}
      </ul>
      <p>Total {order.total} EUR, paid with card ending {order.payment.cardLast4}</p>
      <p>Shipping to {order.customer.name}</p>
      <h2>You may also like</h2>
      <ul>
        {order.recommendations.map((product) => <li key={product.productId}>{product.name}</li>)}
      </ul>
    </article>
  );
}
Frontendweb-app/src/OrderHistoryRow.tsxA second page with a smaller query. It asks only for order fields, so the web BFF calls only the order service. The BFF did not change to support this page.
import { useEffect, useState } from "react";

const ORDER_ROW_QUERY = `
  query OrderRow($id: String!) {
    order(id: $id) {
      number
      placedAt
      total
    }
  }
`;

type OrderRowData = { number: string; placedAt: string; total: number };

export function OrderHistoryRow({ orderId }: { orderId: string }) {
  const [order, setOrder] = useState<OrderRowData | null>(null);

  useEffect(() => {
    fetch("/graphql", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      credentials: "include",
      body: JSON.stringify({ query: ORDER_ROW_QUERY, variables: { id: orderId } }),
    })
      .then((response) => response.json())
      .then((result) => setOrder(result.data.order));
  }, [orderId]);

  if (!order) return null;

  return (
    <tr>
      <td>{order.number}</td>
      <td>{new Date(order.placedAt).toLocaleDateString()}</td>
      <td>{order.total} EUR</td>
    </tr>
  );
}
Frontendmobile-app/src/OrderCard.tsxA React Native card. It calls the mobile BFF's own address, and the reply has only the fields the card shows.
import { useEffect, useState } from "react";
import { Image, Text, View } from "react-native";

type OrderCardData = {
  orderNumber: string;
  status: string;
  total: number;
  itemCount: number;
  thumbnailUrl?: string;
};

export function OrderCard({ orderId }: { orderId: string }) {
  const [card, setCard] = useState<OrderCardData | null>(null);

  useEffect(() => {
    fetch(`https://mobile-api.shop.example.com/bff/orders/${orderId}`)
      .then((response) => response.json())
      .then(setCard);
  }, [orderId]);

  if (!card) return <Text>Loading...</Text>;

  return (
    <View>
      {card.thumbnailUrl && <Image source={{ uri: card.thumbnailUrl }} />}
      <Text>{card.orderNumber}: {card.status}</Text>
      <Text>{card.itemCount} items, {card.total} EUR</Text>
    </View>
  );
}

BFFweb-bff/src/resolvers.tsA GraphQL server built with graphql-yoga. Each resolver calls one service and runs only when the query asks for its field. Sibling fields such as customer and payment resolve at the same time.
import { readFileSync } from "node:fs";
import { createSchema, createYoga } from "graphql-yoga";

async function getJson(url: string) {
  const response = await fetch(url, { signal: AbortSignal.timeout(2000) });
  if (!response.ok) throw new Error(`${url} replied ${response.status}.`);
  return response.json();
}

const resolvers = {
  Query: {
    order: (_parent: unknown, args: { id: string }) =>
      getJson(`${process.env.ORDER_SERVICE_URL}/orders/${args.id}`),
  },
  Order: {
    placedAt: (order: any) => order.createdAt,

    customer: async (order: any) => {
      const user = await getJson(`${process.env.USER_SERVICE_URL}/users/${order.userId}`);
      return { name: user.fullName, email: user.email };
    },

    payment: async (order: any) => {
      const payment = await getJson(`${process.env.PAYMENT_SERVICE_URL}/payments?orderId=${order.id}`);
      return { status: payment.status, cardLast4: payment.card.last4 };
    },

    recommendations: (order: any) =>
      getJson(`${process.env.RECOMMENDATION_SERVICE_URL}/recommendations?orderId=${order.id}`).catch(() => []),
  },
};

export const graphqlServer = createYoga({
  schema: createSchema({ typeDefs: readFileSync("schema.graphql", "utf8"), resolvers }),
});

import { Router } from "express";

async function getJson(url: string) {
  const response = await fetch(url, { signal: AbortSignal.timeout(2000) });
  if (!response.ok) throw new Error(`${url} replied ${response.status}.`);
  return response.json();
}

export const orderCardRoute = Router();

orderCardRoute.get("/bff/orders/:id", async (req, res) => {
  const [order, payment] = await Promise.all([
    getJson(`${process.env.ORDER_SERVICE_URL}/orders/${req.params.id}`),
    getJson(`${process.env.PAYMENT_SERVICE_URL}/payments?orderId=${req.params.id}`),
  ]);

  res.json({
    orderNumber: order.number,
    status: payment.status === "succeeded" ? "Paid" : "Payment pending",
    total: order.total,
    itemCount: order.items.length,
    thumbnailUrl: order.items[0]?.imageUrl,
  });
});
BFFweb-bff/OrderGraph.csA GraphQL server built with Hot Chocolate, registered with AddGraphQLServer().AddQueryType<Query>() and served at /graphql. Each method on OrderFromService is a resolver that runs only when the query asks for its field.
using HotChocolate;

namespace WebBff;

public record OrderItem(string Name, int Quantity, decimal Price);
public record Customer(string Name, string Email);
public record Payment(string Status, string CardLast4);
public record Product(string ProductId, string Name, string ImageUrl);

record UserFromService(string FullName, string Email);
record CardFromService(string Last4);
record PaymentFromService(string Status, CardFromService Card);

public class Query
{
    public Task<OrderFromService?> GetOrder(string id, [Service] IHttpClientFactory http) =>
        http.CreateClient("order-service").GetFromJsonAsync<OrderFromService>($"/orders/{id}");
}

[GraphQLName("Order")]
public class OrderFromService
{
    [GraphQLIgnore] public string Id { get; init; } = "";
    [GraphQLIgnore] public string UserId { get; init; } = "";
    [GraphQLIgnore] public DateTime CreatedAt { get; init; }

    public string Number { get; init; } = "";
    public decimal Total { get; init; }
    public List<OrderItem> Items { get; init; } = [];
    public DateTime PlacedAt => CreatedAt;

    public async Task<Customer> GetCustomer([Service] IHttpClientFactory http)
    {
        var user = await http.CreateClient("user-service").GetFromJsonAsync<UserFromService>($"/users/{UserId}");
        return new Customer(user!.FullName, user.Email);
    }

    public async Task<Payment> GetPayment([Service] IHttpClientFactory http)
    {
        var payment = await http.CreateClient("payment-service").GetFromJsonAsync<PaymentFromService>($"/payments?orderId={Id}");
        return new Payment(payment!.Status, payment.Card.Last4);
    }

    public async Task<List<Product>> GetRecommendations([Service] IHttpClientFactory http)
    {
        try
        {
            return await http.CreateClient("recommendation-service")
                .GetFromJsonAsync<List<Product>>($"/recommendations?orderId={Id}") ?? [];
        }
        catch (HttpRequestException)
        {
            return [];
        }
    }
}
BFFmobile-bff/OrderCardEndpoint.csCalls only 2 services and returns 5 small fields. The Order record declares only what the card needs, and System.Text.Json skips the rest of the reply.
namespace MobileBff;

public record OrderItem(string ImageUrl);
public record Order(string Number, List<OrderItem> Items, decimal Total);
public record Payment(string Status);

public static class OrderCardEndpoint
{
    public static void MapOrderCard(this WebApplication app)
    {
        app.MapGet("/bff/orders/{id}", async (string id, IHttpClientFactory http) =>
        {
            var orderTask = http.CreateClient("order-service").GetFromJsonAsync<Order>($"/orders/{id}");
            var paymentTask = http.CreateClient("payment-service").GetFromJsonAsync<Payment>($"/payments?orderId={id}");
            await Task.WhenAll(orderTask, paymentTask);

            var order = (await orderTask)!;
            var payment = (await paymentTask)!;

            return Results.Ok(new
            {
                orderNumber = order.Number,
                status = payment.Status == "succeeded" ? "Paid" : "Payment pending",
                total = order.Total,
                itemCount = order.Items.Count,
                thumbnailUrl = order.Items.FirstOrDefault()?.ImageUrl,
            });
        });
    }
}
