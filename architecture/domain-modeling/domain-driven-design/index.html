Architecture / Domain modeling

Domain-Driven Design

Usually shortened to DDD. Described by Eric Evans in his 2003 book of the same name.

What it is

A way to design software by modelling the business it serves. Developers and the people who know the business agree on the words, and the code uses those exact words.

DDD has two parts. Strategic design splits the business into bounded contexts, each with its own model and its own words. Tactical design gives building blocks for the code inside one context: entities, value objects, aggregates, domain events and repositories.

DDD is about the model, not about deployment. A bounded context can be a module in a monolith or its own microservice. Teams often use bounded contexts to decide where to split services.

Main rule: each bounded context has its own model and its own words. A context never uses another context's classes. Contexts share only messages, such as OrderPlaced.

What "order" means in each bounded context

The word "order" means something different in each part of the shop. One shared Order class would need every field for every team. DDD gives each context its own model.

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. PlaceOrderHandler receives the command: customer 7 wants 1 desk lamp and 2 LED bulbs, shipped to Oslo.
  2. It creates a new Order. The order is the aggregate root: every change to the aggregate goes through it.
  3. order.addLine(...) creates OrderLine entities. Prices are Money value objects, so euros can never be added to kroner by mistake.
  4. order.place(address) checks the rules: the order is still a draft and has at least one line. Address is a value object: it has no ID.
  5. The handler saves the whole aggregate, the order and all its lines, through OrderRepository in one transaction.
  6. Placing the order recorded an OrderPlaced domain event. The handler publishes it after the save.
  1. OrderPlaced leaves the Sales context as a message. Other contexts never see the Order class itself.
  2. Billing turns the message into an Invoice. It reads only the order ID and the total.
  3. To collect the money, Billing calls Stripe through StripeGateway. It turns Stripe's PaymentIntent statuses into Billing's own PaymentResult.
  4. Shipping turns the same message into a Shipment. It reads only the order ID and the address, and ignores prices.
  1. A request tries to add a line to an order that was already placed.
  2. Order.addLine checks the status and throws "The order is already placed." The order is not changed.
  3. The lines list is read-only from outside, and only Order creates an OrderLine. No other code can change the lines, so the lines and the total always agree.

Problems it solves

  • Code that does not match the businessNames come from the shared glossary. A business expert can read order.place() and check the rules.
  • One huge shared modelInstead of one Order class with every field for every team, each context has a small model of its own.
  • Business rules spread across the codeThe rules live in the aggregate. No other code can create an order that breaks them.
  • Unclear module or service boundariesBounded contexts give clear lines for splitting modules or services.
  • A change in one area breaks anotherBilling can change Invoice without touching Sales, because they share only the event.
  • Outside systems leak into your codeThe anti-corruption layer keeps Stripe's terms at the edge of Billing.

Problems it introduces

  • Many new terms to learnEntities, value objects, aggregates, contexts. Teams often copy the patterns without the reasons behind them.
  • Needs business expertsThe model depends on regular talks with people who know the business. Without them, it is guesswork.
  • Too much for simple appsFor a form that saves rows to a table, aggregates and value objects add code without adding value.
  • Mapping codeAggregates must be mapped to tables, and domain events to messages. This is extra code or ORM setup.
  • Data copied between contextsShipping keeps its own copy of the address. Copies can be out of date for a short time.
  • Choosing aggregate size is hardToo big, and saves conflict and load slowly. Too small, and rules across aggregates need events and delays.

# Glossary

## Sales
- Order: what a customer is buying. Has lines, a total and a status: draft or placed.
- Order line: one product with its unit price and quantity.
- Place an order: the customer confirms the order. After this, the lines cannot change.

## Billing
- Invoice: the amount to collect for one placed order.
- Collect: take payment for an invoice.

## Shipping
- Shipment: a parcel for one placed order, with a delivery address.
- Hand over: give the shipment to a carrier and get a tracking number.
Aggregate rootsales/domain/Order.tsAll changes go through these methods, and each one checks the rules first. The lines are read-only from outside. Placing the order records an OrderPlaced event.
import { randomUUID } from "node:crypto";
import { Address } from "./Address";
import { Money } from "./Money";
import { OrderLine } from "./OrderLine";
import { OrderPlaced } from "./OrderPlaced";

type OrderStatus = "draft" | "placed";

export class Order {
  private readonly orderLines: OrderLine[] = [];
  private status: OrderStatus = "draft";
  readonly events: OrderPlaced[] = [];

  constructor(
    readonly id: string,
    readonly customerId: string,
    readonly currency: string,
  ) {}

  get lines(): readonly OrderLine[] {
    return this.orderLines;
  }

  get total(): Money {
    return this.orderLines.reduce((sum, line) => sum.add(line.subtotal), Money.zero(this.currency));
  }

  addLine(productId: string, unitPrice: Money, quantity: number): void {
    if (this.status !== "draft") throw new Error("The order is already placed.");
    if (this.orderLines.length >= 50) throw new Error("An order can have at most 50 lines.");

    this.orderLines.push(new OrderLine(randomUUID(), productId, unitPrice, quantity));
  }

  place(shippingAddress: Address): void {
    if (this.status !== "draft") throw new Error("The order is already placed.");
    if (this.orderLines.length === 0) throw new Error("An order needs at least one line.");

    this.status = "placed";
    this.events.push({ orderId: this.id, customerId: this.customerId, total: this.total, shippingAddress });
  }
}

Value objectsales/domain/Money.tsNo ID, and it never changes after it is made. Every method returns a new Money. Two values with the same amount and currency are equal.
export class Money {
  private constructor(
    readonly cents: number,
    readonly currency: string,
  ) {}

  static of(amount: number, currency: string): Money {
    if (amount < 0) throw new Error("An amount cannot be negative.");
    return new Money(Math.round(amount * 100), currency);
  }

  static zero(currency: string): Money {
    return new Money(0, currency);
  }

  add(other: Money): Money {
    if (other.currency !== this.currency) {
      throw new Error(`Cannot add ${other.currency} to ${this.currency}.`);
    }
    return new Money(this.cents + other.cents, this.currency);
  }

  times(quantity: number): Money {
    return new Money(this.cents * quantity, this.currency);
  }

  equals(other: Money): boolean {
    return this.cents === other.cents && this.currency === other.currency;
  }
}

Application servicesales/application/PlaceOrderHandler.tsRuns the use case step by step but holds no business rules. Those live in Order.
import { randomUUID } from "node:crypto";
import { Address } from "../domain/Address";
import { Money } from "../domain/Money";
import { Order } from "../domain/Order";
import { OrderRepository } from "../domain/OrderRepository";

export interface EventPublisher {
  publishAll(events: object[]): Promise<void>;
}

export type PlaceOrderCommand = {
  customerId: string;
  lines: { productId: string; unitPrice: number; quantity: number }[];
  address: { street: string; city: string; postcode: string; country: string };
};

export class PlaceOrderHandler {
  constructor(
    private readonly orders: OrderRepository,
    private readonly events: EventPublisher,
  ) {}

  async handle(command: PlaceOrderCommand): Promise<string> {
    const order = new Order(randomUUID(), command.customerId, "EUR");
    for (const line of command.lines) {
      order.addLine(line.productId, Money.of(line.unitPrice, "EUR"), line.quantity);
    }

    const { street, city, postcode, country } = command.address;
    order.place(new Address(street, city, postcode, country));

    await this.orders.save(order);
    await this.events.publishAll(order.events);
    return order.id;
  }
}

Anti-corruption layerbilling/infrastructure/StripeGateway.tsStripe's words, such as PaymentIntent and requires_action, stop here. The rest of Billing only sees PaymentResult, in Billing's own words.
import Stripe from "stripe";

export type PaymentResult =
  | { outcome: "collected"; reference: string }
  | { outcome: "declined"; reason: string }
  | { outcome: "needs-customer-action" }
  | { outcome: "pending" };

export class StripeGateway {
  constructor(private readonly stripe: Stripe) {}

  async collect(amountDueCents: number, currency: string, paymentMethodId: string): Promise<PaymentResult> {
    try {
      const paymentIntent = await this.stripe.paymentIntents.create({
        amount: amountDueCents,
        currency: currency.toLowerCase(),
        payment_method: paymentMethodId,
        confirm: true,
      });

      switch (paymentIntent.status) {
        case "succeeded":
          return { outcome: "collected", reference: paymentIntent.id };
        case "requires_action":
          return { outcome: "needs-customer-action" };
        default:
          return { outcome: "pending" };
      }
    } catch (error) {
      if (error instanceof Stripe.errors.StripeCardError) {
        return { outcome: "declined", reason: error.message };
      }
      throw error;
    }
  }
}

Aggregate rootsrc/Shop.Sales/Domain/Order.csAll changes go through these methods, and each one checks the rules first. Lines is read-only from outside. Placing the order records an OrderPlaced event.
namespace Shop.Sales.Domain;

public enum OrderStatus { Draft, Placed }

public class Order
{
    private readonly List<OrderLine> lines = [];
    private readonly List<OrderPlaced> events = [];

    public Order(Guid id, Guid customerId, string currency)
    {
        Id = id;
        CustomerId = customerId;
        Currency = currency;
    }

    public Guid Id { get; }
    public Guid CustomerId { get; }
    public string Currency { get; }
    public OrderStatus Status { get; private set; } = OrderStatus.Draft;
    public IReadOnlyList<OrderLine> Lines => lines;
    public IReadOnlyList<OrderPlaced> Events => events;

    public Money Total => lines.Aggregate(Money.Zero(Currency), (sum, line) => sum.Add(line.Subtotal));

    public void AddLine(string productId, Money unitPrice, int quantity)
    {
        if (Status != OrderStatus.Draft) throw new InvalidOperationException("The order is already placed.");
        if (lines.Count >= 50) throw new InvalidOperationException("An order can have at most 50 lines.");

        lines.Add(new OrderLine(Guid.NewGuid(), productId, unitPrice, quantity));
    }

    public void Place(Address shippingAddress)
    {
        if (Status != OrderStatus.Draft) throw new InvalidOperationException("The order is already placed.");
        if (lines.Count == 0) throw new InvalidOperationException("An order needs at least one line.");

        Status = OrderStatus.Placed;
        events.Add(new OrderPlaced(Id, CustomerId, Total, shippingAddress));
    }
}

public sealed record Money
{
    private Money(long cents, string currency)
    {
        Cents = cents;
        Currency = currency;
    }

    public long Cents { get; }
    public string Currency { get; }

    public static Money Of(decimal amount, string currency) =>
        amount < 0
            ? throw new ArgumentException("An amount cannot be negative.")
            : new Money((long)Math.Round(amount * 100), currency);

    public static Money Zero(string currency) => new(0, currency);

        other.Currency == Currency
            ? new Money(Cents + other.Cents, Currency)

    public Money Times(int quantity) => new(Cents * quantity, Currency);
}

Anti-corruption layersrc/Shop.Billing/Infrastructure/StripeGateway.csStripe's words, such as PaymentIntent and requires_action, stop here. The rest of Billing only sees PaymentResult, in Billing's own words.
using Stripe;

namespace Shop.Billing.Infrastructure;

public abstract record PaymentResult
{
    public sealed record Collected(string Reference) : PaymentResult;
    public sealed record Declined(string Reason) : PaymentResult;
    public sealed record NeedsCustomerAction : PaymentResult;
    public sealed record Pending : PaymentResult;
}

public class StripeGateway(PaymentIntentService stripePayments)
{
    public async Task<PaymentResult> CollectAsync(long amountDueCents, string currency, string paymentMethodId)
    {
        try
        {
            var paymentIntent = await stripePayments.CreateAsync(new PaymentIntentCreateOptions
            {
                Amount = amountDueCents,
                Currency = currency.ToLowerInvariant(),
                PaymentMethod = paymentMethodId,
                Confirm = true,
            });

            return paymentIntent.Status switch
            {
                "succeeded" => new PaymentResult.Collected(paymentIntent.Id),
                "requires_action" => new PaymentResult.NeedsCustomerAction(),
                _ => new PaymentResult.Pending(),
            };
        }
        catch (StripeException error) when (error.StripeError?.Type == "card_error")
        {
            return new PaymentResult.Declined(error.Message);
        }
    }
}
