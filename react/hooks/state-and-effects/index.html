React / Hooks

React State and Effects

How a function component remembers values between renders, and how it works with things outside React. Examples use React 19.

What it is

A component is a function, and React calls it again on every render. Its local variables start fresh each time. Hooks are functions whose names start with use; they let the component keep data that React stores for it between calls.

React stores hook data in a list per component instance, in the order the hooks are called. On the next render, the first useState call gets the first stored value, the second gets the second, and so on. That is why hooks must be called in the same order on every render: never inside an if, a loop or after an early return.

useEffect is for working with systems outside React: a network request, a timer, a browser API, a subscription. React runs it after the screen is updated, and runs its cleanup before the next run and when the component is removed.

Main rule: compute what you can during render, change state in event handlers, and use effects only to sync with something outside React. Every effect that starts something must clean it up.

React compares each dependency with Object.is. The react-hooks/exhaustive-deps lint rule lists the values the effect reads, so none are forgotten.

Problems it solves

  • State in plain functionsFunction components keep values between renders without classes.
  • Setup and teardown kept togetherAn effect's subscribe and unsubscribe code sit in one place.
  • Reusing stateful logicA custom hook such as useSearchResults packages state and effects for any component.
  • Old work cancelledCleanup runs before the next effect, so outdated requests and timers can be stopped.

Problems it introduces

  • Order rulesHooks cannot be called conditionally, which feels strange for normal functions.
  • Dependency mistakesMissing values give stale data; new objects give effects that run every render.
  • Effects used for everythingExtra renders and bugs from effects that only copy one state into another.
  • RacesNetwork responses can arrive in a different order than requests, unless cleanup handles it.
Componentsrc/search/SearchPage.tsxThe component holds the query and calls a custom hook for the results. The input changes state in its event handler. The summary text is computed from props, not stored.
import { useState } from "react";
import { ResultSummary } from "./ResultSummary";
import { useSearchResults } from "./useSearchResults";

export function SearchPage() {
  const [query, setQuery] = useState("");
  const { results, isLoading } = useSearchResults(query);

  return (
    <main>
      <input value={query} onChange={(event) => setQuery(event.target.value)} placeholder="Search products" />
      <ResultSummary query={query} resultCount={results.length} isLoading={isLoading} />
      <ul>
        {results.map((product) => (
          <li key={product.id}>{product.name}</li>
        ))}
      </ul>
    </main>
  );
}
Effectsrc/search/useSearchResults.tsThe effect depends on query, a string, so it runs only when the text changes. The cleanup aborts the request of the previous query, so an old response can never replace a newer one. An aborted request is expected and not reported. The ref keeps the start time for the duration metric without causing a render. For real apps, TanStack Query does this, plus caching and retries.
import { useEffect, useRef, useState } from "react";
import { reportMetric } from "../monitoring";
import { searchProducts, type Product } from "./searchClient";

export function useSearchResults(query: string) {
  const [results, setResults] = useState<Product[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const searchStartedAt = useRef(0);

  useEffect(() => {
    if (query.length < 2) {
      setResults([]);
      return;
    }

    const abortController = new AbortController();
    searchStartedAt.current = performance.now();
    setIsLoading(true);

    searchProducts(query, abortController.signal)
      .then((products) => {
        setResults(products);
        reportMetric("search_results_ms", Math.round(performance.now() - searchStartedAt.current));
      })
      .catch(() => {
        if (abortController.signal.aborted) return;
        setResults([]);
      })
      .finally(() => {
        if (!abortController.signal.aborted) setIsLoading(false);
      });

    return () => abortController.abort();
  }, [query]);

  return { results, isLoading };
}
Serversrc/search/searchClient.tsThe client logs a failed response once, with the server's x-request-id, so the error can be found in the server's logs. The query text is not logged: users type personal data into search boxes. Aborts throw before a response exists, so they never reach the report.
import { reportError } from "../monitoring";

export type Product = { id: string; name: string };

export async function searchProducts(query: string, signal: AbortSignal): Promise<Product[]> {
  const response = await fetch(`/api/search?q=${encodeURIComponent(query)}`, { signal });

  if (!response.ok) {
    const error = new Error(`Search failed with status ${response.status}.`);
    reportError(error, { path: "/api/search", status: response.status, requestId: response.headers.get("x-request-id") });
    throw error;
  }
  return (await response.json()) as Product[];
}
Statesrc/search/ResultSummary.tsxThe summary is derived during render. A common alternative keeps it in useState and updates it in an effect, which shows the old text for one render and adds a hook. Computing it needs neither.
type ResultSummaryProps = { query: string; resultCount: number; isLoading: boolean };

export function ResultSummary({ query, resultCount, isLoading }: ResultSummaryProps) {
  if (query.length < 2) return <p>Type at least 2 characters.</p>;
  if (isLoading) return <p>Searching...</p>;

  const resultCountText = resultCount === 1 ? "1 result" : `${resultCount} results`;
  return <p>{resultCountText} for "{query}"</p>;
}
Refsrc/search/useElapsedTime.tsThe interval ID is kept in a ref: the code needs it to stop the timer, but the screen never shows it. The updater form seconds => seconds + 1 avoids a stale closure: the interval was created in the first render, but always adds to the latest value.
import { useEffect, useRef, useState } from "react";

export function useElapsedTime(isRunning: boolean) {
  const [elapsedSeconds, setElapsedSeconds] = useState(0);
  const intervalId = useRef<ReturnType<typeof setInterval> | null>(null);

  useEffect(() => {
    if (!isRunning) return;
    intervalId.current = setInterval(() => setElapsedSeconds((seconds) => seconds + 1), 1000);
    return () => {
      if (intervalId.current) clearInterval(intervalId.current);
    };
  }, [isRunning]);

  return elapsedSeconds;
}
Hook ordersrc/search/FilterPanel.tsxThe hook is called on every render, before any condition, so the hook list always has the same length. Only the use of its value depends on showFilters. Putting useState inside the if threw Rendered more hooks than during the previous render. in React 19.
import { useState } from "react";

export function FilterPanel({ showFilters }: { showFilters: boolean }) {
  const [sortOrder, setSortOrder] = useState("relevance");
  const [category, setCategory] = useState("all");

  return (
    <div>
      <select value={sortOrder} onChange={(event) => setSortOrder(event.target.value)}>
        <option value="relevance">Relevance</option>
        <option value="price">Price</option>
      </select>
      {showFilters && (
        <select value={category} onChange={(event) => setCategory(event.target.value)}>
          <option value="all">All</option>
          <option value="books">Books</option>
        </select>
      )}
    </div>
  );
}
