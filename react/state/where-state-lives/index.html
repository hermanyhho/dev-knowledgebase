React / State

Where React State Lives

Choosing the right place for each piece of data: a component, a parent, the URL, a context, or a cache of server data. Examples use React 19, TanStack Query 5 and React Router 8.

What it is

Not all state is the same. A dropdown that is open, the filters on a product list, the logged-in user and the products loaded from the server change for different reasons and are needed by different parts of the page. Putting all of it in useState at the top of the app makes every change render everything, and copies of server data go out of date.

Each kind of state has a place where it works best. The question for each value is: who needs it, how long must it survive, and where is the real copy?

Main rule: keep state as low in the tree as possible and only as high as needed. Data from the server goes in a query cache, not in useState. Anything a link should reproduce goes in the URL.

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The user picks "books" in the filters. The handler writes it to the URL: ?category=books&page=1. No useState holds it.
  2. The URL changed, so ProductsPage renders and reads the new filters from it.
  3. It asks the query cache for ["products", { category: "books", page: 1 }]. That key is not cached yet, so the cache fetches it.
  4. The products arrive and the list renders. The previous key stays cached for a while.
  5. The user presses Back. The URL returns to the old filters, and the old key is shown at once from the cache. A copied link opens the same filtered page.
  1. The user types 1 in a card's quantity input, which is local state, and clicks Add. The badge says 2 items.
  2. The card runs a mutation: POST /api/cart/items. On success it calls invalidateQueries({ queryKey: ["cart"] }).
  3. The cart query is marked stale. CartBadge reads it, so the cache refetches it.
  4. The badge shows 3 items. The card and the badge never passed anything to each other: both talk to the cache.
  1. The header's CartBadge calls useCart(), which is useQuery({ queryKey: ["cart"] }).
  2. On the same page, a mini cart in ProductsPage also calls useCart(). Same key: the cache sends one request and gives both the result.
  3. For 30 seconds, the staleTime, other readers get the cached cart with no request.
  4. With useState and an effect in each component, there would be two requests and two copies that can disagree.
  1. The user provider passes value={{ user, logout }}. Components such as ProductCard read the user to show member prices.
  2. Something unrelated makes App render, for example a toast message in its state.
  3. The provider creates a new value object. React compares it with Object.is, sees a change, and renders every component that reads the context.
  4. Memoize the value with useMemo, or let the React Compiler do it, and keep often-changing data out of context.
  1. An edit form loads a product with useQuery and puts it into useState(product) to edit it.
  2. useState uses its argument only on the first render. When the query refetches newer data, the form keeps the first copy.
  3. The user saves and overwrites a change someone else made in between.
  4. Read from the query while showing data. If a form needs its own copy, render it with key={product.updatedAt} so new data creates a new form, and let the server reject old versions.

shop-web/

Problems it solves

  • Everything renders on every changeState placed low renders only the components that use it.
  • Out-of-date server dataA query cache refetches stale data and updates every reader.
  • Links that lose the viewFilters and pages in the URL survive reloads, Back and shared links.
  • Props passed through many layersContext and the query cache reach distant components directly.

Problems it introduces

  • More places to lookA value can be in props, the URL, a context, the cache or a store.
  • Cache rules to learnQuery keys, stale time and invalidation decide when data refreshes.
  • URL parsingURL values are strings and can be edited by hand, so they must be checked.
  • Context rendersA frequently changing context renders every reader.
Setupsrc/App.tsxOne QueryClient for the app. The caches' onError callbacks report every failed query and mutation once, with the first part of the key as its name, so components do not each log errors. staleTime of 30 seconds means data younger than that is used without a request.
import { MutationCache, QueryCache, QueryClient, QueryClientProvider } from "@tanstack/react-query";
import { BrowserRouter, Route, Routes } from "react-router";
import { CartBadge } from "./layout/CartBadge";
import { reportError } from "./monitoring";
import { ProductsPage } from "./products/ProductsPage";
import { CurrentUserProvider } from "./user/CurrentUserContext";

const queryClient = new QueryClient({
  queryCache: new QueryCache({
    onError: (error, query) => reportError(error, { kind: "query", name: String(query.queryKey[0]) }),
  }),
  mutationCache: new MutationCache({
    onError: (error, _variables, _context, mutation) => reportError(error, { kind: "mutation", name: String(mutation.options.mutationKey?.[0]) }),
  }),
  defaultOptions: { queries: { staleTime: 30_000 } },
});

export function App() {
  return (
    <QueryClientProvider client={queryClient}>
      <CurrentUserProvider>
        <BrowserRouter>
          <header>
            <CartBadge />
          </header>
          <Routes>
            <Route path="/products" element={<ProductsPage />} />
          </Routes>
        </BrowserRouter>
      </CurrentUserProvider>
    </QueryClientProvider>
  );
}
Contextsrc/user/CurrentUserContext.tsxThe provider memoizes its value, so readers render only when the user changes, not every time the provider renders. The hook throws when used outside the provider, which finds setup mistakes at once. The user itself comes from a query, so it stays in the query cache.
import { createContext, useContext, useMemo, type ReactNode } from "react";
import { useCurrentUserQuery, type CurrentUser } from "../queries";

type CurrentUserValue = { user: CurrentUser | null; isMember: boolean };

const CurrentUserContext = createContext<CurrentUserValue | null>(null);

export function CurrentUserProvider({ children }: { children: ReactNode }) {
  const { data: user = null } = useCurrentUserQuery();
  const value = useMemo(() => ({ user, isMember: user?.membership === "gold" }), [user]);
  return <CurrentUserContext value={value}>{children}</CurrentUserContext>;
}

export function useCurrentUser(): CurrentUserValue {
  const value = useContext(CurrentUserContext);
  if (!value) throw new Error("useCurrentUser must be used inside CurrentUserProvider.");
  return value;
}
Pagesrc/products/ProductsPage.tsxThe page holds no state for filters: it reads them from the URL and writes changes back to it. The products come from the query cache with the filters in the key. placeholderData keeps the old list visible while the next page loads.
import { keepPreviousData } from "@tanstack/react-query";
import { useProducts } from "../queries";
import { ProductCard } from "./ProductCard";
import { useProductFilters } from "./useProductFilters";

export function ProductsPage() {
  const [filters, setFilters] = useProductFilters();
  const { data: products = [], isPending, error } = useProducts(filters, { placeholderData: keepPreviousData });

  return (
    <main>
      <select value={filters.category} onChange={(event) => setFilters({ category: event.target.value, page: 1 })}>
        <option value="all">All</option>
        <option value="books">Books</option>
      </select>
      {error && <p role="alert">Products could not be loaded.</p>}
      {isPending ? <p>Loading...</p> : products.map((product) => <ProductCard key={product.id} product={product} />)}
      <button onClick={() => setFilters({ ...filters, page: filters.page + 1 })}>Next page</button>
    </main>
  );
}
Local statesrc/products/ProductCard.tsxThe quantity input matters only inside this card, so it is local state. Adding to the cart is a mutation; the card does not know who shows the cart. isPending disables the button while the request runs, so a double click does not add twice.
import { useState } from "react";
import { useAddToCart, type Product } from "../queries";
import { useCurrentUser } from "../user/CurrentUserContext";

export function ProductCard({ product }: { product: Product }) {
  const [quantity, setQuantity] = useState(1);
  const { isMember } = useCurrentUser();
  const addToCart = useAddToCart();
  const price = isMember ? product.memberPrice : product.price;

  return (
    <article>
      <h3>{product.name}</h3>
      <p>{price.toFixed(2)}</p>
      <input type="number" min={1} value={quantity} onChange={(event) => setQuantity(Number(event.target.value))} />
      <button disabled={addToCart.isPending} onClick={() => addToCart.mutate({ productId: product.id, quantity })}>
        Add to cart
      </button>
    </article>
  );
}
Headersrc/layout/CartBadge.tsxThe badge sits in the header, far from the product cards. It reads the cart from the cache with the same key as every other cart reader, so it updates when the cart query is invalidated.
import { useCart } from "../queries";

export function CartBadge() {
  const { data: cart } = useCart();
  const itemCount = cart?.items.reduce((total, item) => total + item.quantity, 0) ?? 0;
  return <a href="/cart">Cart ({itemCount})</a>;
}
URLsrc/products/useProductFilters.tsThe filters are read from the URL and checked, because anyone can edit a URL: an unknown category becomes "all", a bad page becomes 1. Writing them replaces the search parameters, which adds a history entry, so Back returns to the previous filters.
import { useSearchParams } from "react-router";

export type ProductFilters = { category: string; page: number };

const knownCategories = new Set(["all", "books", "games"]);

export function useProductFilters(): [ProductFilters, (next: ProductFilters) => void] {
  const [searchParams, setSearchParams] = useSearchParams();

  const category = searchParams.get("category") ?? "all";
  const page = Number(searchParams.get("page"));
  const filters = {
    category: knownCategories.has(category) ? category : "all",
    page: Number.isInteger(page) && page > 0 ? page : 1,
  };

  const setFilters = (next: ProductFilters) =>
    setSearchParams({ category: next.category, page: String(next.page) });

  return [filters, setFilters];
}
Server statesrc/queries.tsAll server state in one file. Each query has a key: the same key means the same cached data. The filters are part of the products key, so each filter combination is cached on its own. After adding to the cart, invalidating ["cart"] refetches the cart for every component that shows it.
import { useMutation, useQuery, useQueryClient, type UseQueryOptions } from "@tanstack/react-query";
import type { ProductFilters } from "./products/useProductFilters";

export type Product = { id: string; name: string; price: number; memberPrice: number };
export type Cart = { items: { productId: string; quantity: number }[] };
export type CurrentUser = { id: string; name: string; membership: "basic" | "gold" };

async function getJson<T>(path: string, init?: RequestInit): Promise<T> {
  const response = await fetch(path, init);
  if (!response.ok) {
    throw new Error(`Request failed with status ${response.status}, request ID ${response.headers.get("x-request-id")}.`);
  }
  return (await response.json()) as T;
}

export function useProducts(filters: ProductFilters, options?: Partial<UseQueryOptions<Product[]>>) {
  return useQuery({
    queryKey: ["products", filters],
    queryFn: () => getJson<Product[]>(`/api/products?category=${filters.category}&page=${filters.page}`),
    ...options,
  });
}

export function useCart() {
  return useQuery({ queryKey: ["cart"], queryFn: () => getJson<Cart>("/api/cart") });
}

export function useCurrentUserQuery() {
  return useQuery({ queryKey: ["current-user"], queryFn: () => getJson<CurrentUser>("/api/me"), staleTime: 5 * 60_000 });
}

export function useAddToCart() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationKey: ["add-to-cart"],
    mutationFn: (item: { productId: string; quantity: number }) =>
      getJson<Cart>("/api/cart/items", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify(item) }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ["cart"] }),
  });
}
