React Overview

A library that builds the page from components: functions that describe the screen for the current data. Examples use React 19.

What it is

You write components that return JSX: a description of what the screen should show. When data changes, React calls the components again, compares the new description with the old one, and changes only the parts of the page that differ.

Three ideas cover most of daily React work: how a change becomes a new screen, how a component keeps state and talks to the outside world, and where each piece of state should live.

TopicKey ideaCommon mistake
How React rendersA state change renders the component and everything below it. React compares by element type and key; same type and key keeps state.List keys from the array index
State and effectsuseState keeps values between renders. useEffect syncs with things outside React and cleans up after itself. Hooks are matched by call order.Effects that only copy one state into another
Where state livesLocal state in the component that uses it; shared state in the closest parent; filters in the URL; server data in a query cache such as TanStack Query.Server data copied into useState, which goes out of date
Main rule: keep rendering pure, compute what you can during render, and keep each piece of state in one place: as low in the tree as possible, as high as needed.

Problems it solves

  • Updating the page by handYou describe the result; React changes the DOM.
  • Screens out of step with dataEvery change produces the whole description again.
  • Reusing UIComponents and custom hooks package markup and logic together.

Problems it introduces

  • Extra rendersA change high in the tree renders everything below it.
  • Rules to learnPure render, hook order, dependency arrays and keys.
  • Many places for stateProps, URL, context and caches each fit different data.
StateProductsPage.tsxThe quantity is local state; the category comes from the URL; the products come from the query cache, keyed by the category. Each value lives in one place.
import { useState } from "react";
import { useQuery } from "@tanstack/react-query";
import { useSearchParams } from "react-router";

export function ProductsPage() {
  const [searchParams, setSearchParams] = useSearchParams();
  const category = searchParams.get("category") ?? "all";
  const [quantity, setQuantity] = useState(1);
  const { data: products = [] } = useQuery({
    queryKey: ["products", category],
    queryFn: () => fetch(`/api/products?category=${category}`).then((response) => response.json()),
  });

  return (
    <main>
      <button onClick={() => setSearchParams({ category: "books" })}>Books</button>
      <input type="number" value={quantity} onChange={(event) => setQuantity(Number(event.target.value))} />
      <p>{products.length} products</p>
    </main>
  );
}
RenderGreeting.tsxA pure component: the same props give the same JSX, with no side effects. React may call it more often than you expect, and twice in Strict Mode.
export function Greeting({ name, unreadCount }: { name: string; unreadCount: number }) {
  const message = unreadCount === 0 ? "No new messages" : `${unreadCount} new messages`;
  return (
    <p>
      Hello {name}. {message}.
    </p>
  );
}
KeysTodoList.tsxThe key comes from the data, so React matches each row to the same item after a delete or a reorder, and each row keeps its own state.
type Todo = { id: string; title: string };

export function TodoList({ todos }: { todos: Todo[] }) {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          {todo.title} <input placeholder="note" />
        </li>
      ))}
    </ul>
  );
}
EffectsuseOnlineStatus.tsAn effect for something outside React: the browser's online events. The setup subscribes, the cleanup unsubscribes, so no listener is left behind.
import { useEffect, useState } from "react";

export function useOnlineStatus(): boolean {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const goOnline = () => setIsOnline(true);
    const goOffline = () => setIsOnline(false);
    window.addEventListener("online", goOnline);
    window.addEventListener("offline", goOffline);
    return () => {
      window.removeEventListener("online", goOnline);
      window.removeEventListener("offline", goOffline);
    };
  }, []);

  return isOnline;
}
