Security / Authentication

Sessions and Tokens

The two main ways a server remembers that a user has logged in.

What it is

HTTP keeps nothing between requests. After a user logs in, every later request must carry something that proves who is calling. There are two common ways to do this.

With a session, the server saves the login in a session store, such as Redis, under a long random ID. The browser keeps only that ID, usually in a cookie, and sends it with each request. The server looks the ID up.

With a token, the server puts the user ID and an expiry time inside the token and signs it with a secret key. The client sends the token with each request. The server checks the signature with its key, without looking anything up. The most common token format is the JWT.

Both answer one question: who is calling? That is authentication. Deciding what that caller is allowed to do is a separate step, called authorization.

Main rule: the server must be able to check every request on its own, because HTTP keeps nothing between requests. Whatever proves the login, a session ID or a token, is a secret: keep it away from page scripts and out of logs.

Two choices are mixed up often. A session ID or a token can each be stored in a cookie or elsewhere. "Cookie or header" is about how it travels. "Session or token" is about where the login is saved.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The browser sends POST /login with the email and password, over HTTPS.
  2. The server loads the user and checks the password against the stored hash.
  3. It creates a random session ID and saves session:<ID> with user 7 in Redis, set to expire after 8 hours.
  4. It replies with Set-Cookie: sid=<ID>; HttpOnly; Secure; SameSite=Lax. Page scripts cannot read an HttpOnly cookie.
  1. On every later request to the same site, the browser sends the cookie automatically.
  2. Whichever server copy gets the request looks up the session ID in Redis and finds user 7.
  3. The server handles the request as user 7. If the ID is missing or expired, it replies 401.
  4. To log out, the server deletes the session from Redis. The next request with that cookie fails at once, on every server copy.
  1. The mobile app sends POST /token with the email and password.
  2. The server checks the password the same way.
  3. It builds a token holding the user ID and an expiry 15 minutes ahead, and signs it with its secret key. Nothing is saved on the server.
  4. It returns the token in the response body. The app keeps it in the phone's secure storage.
  1. On every request, the app sends Authorization: Bearer <token>.
  2. The server checks the signature with its key and checks that the token has not expired. It does not call the session store or the database.
  3. Any server copy with the key can do this check, so adding copies needs nothing shared.
  1. An attacker copies a token, for example from a log file that recorded request headers.
  2. The signature is correct and the token has not expired, so the server accepts it. The server cannot tell the attacker from the user.
  3. The server has no saved record to delete, so it cannot cancel the token. The token works until it expires, which is why access tokens should last minutes, not days. The access and refresh tokens page shows how users stay logged in anyway.

Problems it solves

  • Sending the password with every requestThe client sends a session ID or token instead. It expires, and it is not the password.
  • Logging a user out at once (sessions)Deleting the session ends the login on every server copy, on the next request.
  • A shared store on every request (tokens)The server checks the signature with its key. There is no lookup, so adding server copies is easy.
  • Passing the login to other services (tokens)The token can travel with a call to another service, which checks it with the same key.
  • Scripts in the page reading the secret (HttpOnly cookie)The browser sends the cookie but never shows it to page scripts.

Problems it introduces

  • A shared store to run (sessions)Redis must stay up and be reachable from every server copy. If it is down, nobody is logged in.
  • Requests sent from other sites (cookies)The browser adds cookies automatically, so another site can trigger requests. SameSite and CSRF tokens prevent this.
  • Tokens cannot be cancelled earlyA copied token works until it expires. Short lifetimes or a list of blocked tokens limit the damage.
  • Bigger requests (tokens)A token holds data and a signature, so it is much larger than a session ID, and it is sent with every request.
  • Key handling (tokens)Anyone with the signing key can create valid tokens for any user. The key must be secret and changed from time to time.

Password checkapi/src/users.tsPasswords are stored only as hashes made with Argon2, a hash built to be slow so guessing is expensive. The server never stores or logs the password itself.
import argon2 from "argon2";
import { Pool } from "pg";

export type User = { id: string; email: string; password_hash: string };

const db = new Pool();

export async function findUserByEmail(email: string): Promise<User | null> {
  const result = await db.query<User>(
    "SELECT id, email, password_hash FROM users WHERE email = $1",
    [email],
  );
  return result.rows[0] ?? null;
}

export function isPasswordCorrect(user: User, password: string): Promise<boolean> {
  return argon2.verify(user.password_hash, password);
}
Sessionsapi/src/sessionAuth.tsWritten out by hand to show each step. In a real app, express-session with a Redis store does the same. The login error is the same for an unknown email and a wrong password, so it does not reveal which accounts exist. Needs the cookie-parser middleware.
import { randomBytes } from "node:crypto";
import { NextFunction, Request, Response, Router } from "express";
import { Redis } from "ioredis";
import { Logger } from "pino";
import { findUserByEmail, isPasswordCorrect } from "./users";

const cookieName = "sid";
const sessionLifetimeSeconds = 8 * 60 * 60;

export function sessionRoutes(redis: Redis, logger: Logger): Router {
  const router = Router();

  router.post("/login", async (req, res) => {
    const user = await findUserByEmail(req.body.email);
    if (!user || !(await isPasswordCorrect(user, req.body.password))) {
      logger.warn({ ip: req.ip, userAgent: req.get("user-agent") }, "login failed");
      return res.status(401).json({ error: "The email or password is wrong." });
    }

    const sessionId = randomBytes(32).toString("base64url");
    await redis.set(
      `session:${sessionId}`,
      JSON.stringify({ userId: user.id, createdAt: new Date().toISOString() }),
      "EX",
      sessionLifetimeSeconds,
    );

    res.cookie(cookieName, sessionId, {
      httpOnly: true,
      secure: true,
      sameSite: "lax",
      maxAge: sessionLifetimeSeconds * 1000,
    });
    logger.info({ userId: user.id, ip: req.ip, method: "session" }, "login succeeded");
    res.status(204).end();
  });

  router.post("/logout", async (req, res) => {
    const sessionId = req.cookies[cookieName];
    if (sessionId) await redis.del(`session:${sessionId}`);
    res.clearCookie(cookieName);
    res.status(204).end();
  });

  return router;
}

export function requireSession(redis: Redis) {
  return async (req: Request, res: Response, next: NextFunction) => {
    const sessionId = req.cookies[cookieName];
    const storedSession = sessionId ? await redis.get(`session:${sessionId}`) : null;
    if (!storedSession) {
      return res.status(401).json({ error: "You are not logged in." });
    }

    res.locals.userId = JSON.parse(storedSession).userId;
    next();
  };
}
Tokensapi/src/tokenAuth.tsUses the jose library. Checking a token needs only the key: no store, no database. The token cannot be cancelled before it expires, so it lives 15 minutes. Issuer and audience checks are covered on the JWT page.
import { NextFunction, Request, Response, Router } from "express";
import { SignJWT, jwtVerify } from "jose";
import { Logger } from "pino";
import { findUserByEmail, isPasswordCorrect } from "./users";

const signingKey = new TextEncoder().encode(process.env.AUTH_TOKEN_KEY);
const tokenLifetimeSeconds = 15 * 60;

export function tokenRoutes(logger: Logger): Router {
  const router = Router();

  router.post("/token", async (req, res) => {
    const user = await findUserByEmail(req.body.email);
    if (!user || !(await isPasswordCorrect(user, req.body.password))) {
      logger.warn({ ip: req.ip, userAgent: req.get("user-agent") }, "login failed");
      return res.status(401).json({ error: "The email or password is wrong." });
    }

    const accessToken = await new SignJWT({})
      .setProtectedHeader({ alg: "HS256" })
      .setSubject(user.id)
      .setIssuedAt()
      .setExpirationTime(`${tokenLifetimeSeconds}s`)
      .sign(signingKey);

    logger.info({ userId: user.id, ip: req.ip, method: "token" }, "login succeeded");
    res.json({ accessToken, expiresIn: tokenLifetimeSeconds });
  });

  return router;
}

export async function requireToken(req: Request, res: Response, next: NextFunction) {
  const header = req.get("authorization") ?? "";
  const token = header.startsWith("Bearer ") ? header.slice("Bearer ".length) : null;

  try {
    if (!token) throw new Error("missing token");
    const { payload } = await jwtVerify(token, signingKey, { algorithms: ["HS256"] });
    res.locals.userId = payload.sub;
    next();
  } catch {
    res.status(401).json({ error: "The token is missing, expired or not valid." });
  }
}
Password checksrc/Api/Auth/Users.csUses PasswordHasher from ASP.NET Core Identity, which hashes with PBKDF2 and many rounds so guessing is expensive. The server never stores or logs the password itself.
using Dapper;
using Microsoft.AspNetCore.Identity;
using Npgsql;

namespace Api.Auth;

public record User(Guid Id, string Email, string PasswordHash);

public class Users(NpgsqlDataSource db)
{
    private static readonly PasswordHasher<User> Hasher = new();

    public async Task<User?> FindByEmailAsync(string email)
    {
        await using var connection = await db.OpenConnectionAsync();
        return await connection.QuerySingleOrDefaultAsync<User>(
            "SELECT id, email, password_hash AS PasswordHash FROM users WHERE email = @email",
            new { email });
    }

    public static bool IsPasswordCorrect(User user, string password) =>
        Hasher.VerifyHashedPassword(user, user.PasswordHash, password) != PasswordVerificationResult.Failed;
}
Sessionssrc/Api/Auth/SessionAuth.csWritten out by hand to show each step. ASP.NET Core's cookie authentication with a Redis SessionStore does the same in a real app. The login error is the same for an unknown email and a wrong password, so it does not reveal which accounts exist.
using System.Security.Cryptography;
using System.Text.Json;
using Microsoft.AspNetCore.WebUtilities;
using StackExchange.Redis;

namespace Api.Auth;

public record LoginRequest(string Email, string Password);
record StoredSession(Guid UserId, DateTimeOffset CreatedAt);

public static class SessionAuth
{
    private const string CookieName = "sid";
    private static readonly TimeSpan SessionLifetime = TimeSpan.FromHours(8);

    public static void MapSessionEndpoints(this WebApplication app)
    {
        app.MapPost("/login", async (LoginRequest request, Users users, IConnectionMultiplexer redis, HttpContext http, ILogger<Users> logger) =>
        {
            var user = await users.FindByEmailAsync(request.Email);
            if (user is null || !Users.IsPasswordCorrect(user, request.Password))
            {
                logger.LogWarning("Login failed from {Ip}, user agent {UserAgent}",
                    http.Connection.RemoteIpAddress, http.Request.Headers.UserAgent.ToString());
                return Results.Json(new { error = "The email or password is wrong." }, statusCode: 401);
            }

            var sessionId = WebEncoders.Base64UrlEncode(RandomNumberGenerator.GetBytes(32));
            await redis.GetDatabase().StringSetAsync(
                $"session:{sessionId}",
                JsonSerializer.Serialize(new StoredSession(user.Id, DateTimeOffset.UtcNow)),
                SessionLifetime);

            http.Response.Cookies.Append(CookieName, sessionId, new CookieOptions
            {
                HttpOnly = true,
                Secure = true,
                SameSite = SameSiteMode.Lax,
                MaxAge = SessionLifetime,
            });
            logger.LogInformation("Login succeeded for user {UserId} with a session", user.Id);
            return Results.NoContent();
        });

        app.MapPost("/logout", async (IConnectionMultiplexer redis, HttpContext http) =>
        {
            if (http.Request.Cookies.TryGetValue(CookieName, out var sessionId))
                await redis.GetDatabase().KeyDeleteAsync($"session:{sessionId}");

            http.Response.Cookies.Delete(CookieName);
            return Results.NoContent();
        });
    }

    public static RouteHandlerBuilder RequireSession(this RouteHandlerBuilder endpoint) =>
        endpoint.AddEndpointFilter(async (context, next) =>
        {
            var http = context.HttpContext;
            var redis = http.RequestServices.GetRequiredService<IConnectionMultiplexer>();
            var storedSession = http.Request.Cookies.TryGetValue(CookieName, out var sessionId)
                ? await redis.GetDatabase().StringGetAsync($"session:{sessionId}")
                : RedisValue.Null;

            if (storedSession.IsNullOrEmpty)
                return Results.Json(new { error = "You are not logged in." }, statusCode: 401);

            http.Items["UserId"] = JsonSerializer.Deserialize<StoredSession>(storedSession.ToString())!.UserId;
            return await next(context);
        });
}
Tokenssrc/Api/Auth/TokenAuth.csASP.NET Core's JWT bearer handler checks every request that needs a login: signature, algorithm and expiry. Checking needs only the key. The token cannot be cancelled before it expires, so it lives 15 minutes. Issuer and audience checks are covered on the JWT page.
using System.Security.Claims;
using System.Text;
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.JsonWebTokens;
using Microsoft.IdentityModel.Tokens;

namespace Api.Auth;

public static class TokenAuth
{
    private static readonly TimeSpan TokenLifetime = TimeSpan.FromMinutes(15);

    private static SymmetricSecurityKey SigningKey(IConfiguration configuration) =>
        new(Encoding.UTF8.GetBytes(configuration["AUTH_TOKEN_KEY"]!));

    public static void AddTokenAuthentication(this IServiceCollection services, IConfiguration configuration) =>
        services
            .AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
            .AddJwtBearer(options => options.TokenValidationParameters = new TokenValidationParameters
            {
                IssuerSigningKey = SigningKey(configuration),
                ValidAlgorithms = [SecurityAlgorithms.HmacSha256],
                ValidateIssuer = false,
                ValidateAudience = false,
                ClockSkew = TimeSpan.FromSeconds(30),
            });

    public static void MapTokenEndpoint(this WebApplication app) =>
        app.MapPost("/token", async (LoginRequest request, Users users, IConfiguration configuration, HttpContext http, ILogger<Users> logger) =>
        {
            var user = await users.FindByEmailAsync(request.Email);
            if (user is null || !Users.IsPasswordCorrect(user, request.Password))
            {
                logger.LogWarning("Login failed from {Ip}, user agent {UserAgent}",
                    http.Connection.RemoteIpAddress, http.Request.Headers.UserAgent.ToString());
                return Results.Json(new { error = "The email or password is wrong." }, statusCode: 401);
            }

            var accessToken = new JsonWebTokenHandler().CreateToken(new SecurityTokenDescriptor
            {
                Subject = new ClaimsIdentity([new Claim(JwtRegisteredClaimNames.Sub, user.Id.ToString())]),
                Expires = DateTime.UtcNow.Add(TokenLifetime),
                SigningCredentials = new SigningCredentials(SigningKey(configuration), SecurityAlgorithms.HmacSha256),
            });

            logger.LogInformation("Login succeeded for user {UserId} with a token", user.Id);
            return Results.Ok(new { accessToken, expiresIn = (int)TokenLifetime.TotalSeconds });
        });
}
