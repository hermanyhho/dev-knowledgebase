Security / Authentication

JWT

Short for JSON Web Token, defined in RFC 7519. Usually said "jot".

What it is

A JWT is a token made of three parts joined by dots: a header, a payload and a signature. The header and payload are JSON, encoded so they fit in a URL or HTTP header. The payload holds claims: statements such as "this is user 7" and "valid until 09:15".

The signature proves two things: the token was made by someone with the signing key, and nobody changed it afterwards. It does not hide anything. Anyone who has the token can decode and read the payload.

On the sessions and tokens page, one server both made and checked tokens with a shared secret. This page shows the common setup with several APIs: one auth server signs tokens with a private key, and each API checks them with the matching public key, which the auth server publishes.

Main rule: anyone can read a JWT. An API may trust it only after checking the signature, the algorithm, the expiry, the issuer and the audience.

How a shared secret compares with a key pair

Shared secret (HS256)Key pair (ES256 or RS256)
Who can create tokensAnyone with the secretOnly the holder of the private key
Who can check tokensOnly those with the same secretAnyone with the public key, which is safe to publish
Giving keys to APIsCopy the secret to every API. Each copy could be used to create tokens.APIs read the public key from the JWKS URL
Good forOne app that creates and checks its own tokensOne auth server and many APIs, or other companies' APIs

What an API must check, in this order

CheckWhat goes wrong if it is skipped
1. The algorithm is the one you expect, such as ES256An attacker sets "alg": "none" to skip the signature, or switches RS256 to HS256 so the public key is used as a shared secret. Never let the token choose the algorithm.
2. The signature, with the key named by kidAnyone can write a token for any user.
3. exp and nbf, allowing at most about 30 seconds of clock differenceA copied token keeps working forever.
4. iss is your auth serverTokens from another auth server that uses the same library are accepted.
5. aud is this APIA token meant for a different API, perhaps a less trusted one, works here too.

After these checks the API knows who is calling. Whether that caller may do the action, for example by reading the scope claim, is authorization, which comes next.

Common mistakes

MistakeDo this instead
Putting an email, address or secret in the payloadAnyone can decode it. Put only IDs and the claims APIs need.
Reading the payload without checking the signature, for example with a decode functionAlways use the library's verify function.
Lifetimes of hours or days5 to 15 minutes, with refresh tokens to get new ones.
Adding every role and permission to the tokenThe token is sent with every request and grows fast. Keep it small and look up details on the server.
Using the same signing key foreverRotate keys. The kid header and the JWKS URL let old and new keys work side by side.
Storing the token in localStorage in a browserAny injected script can read it. Keep it in memory or use an HttpOnly cookie.

Diagram

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The app logs in at the auth server and asks for a token for the orders API.
  2. The auth server builds the header (alg ES256, kid 2026-10) and the payload (iss, sub 7, aud orders-api, exp in 15 minutes, a jti), then signs both with its private key.
  3. It returns the JWT: three base64url parts joined by dots.
  4. The app calls the orders API with Authorization: Bearer <JWT>.
  5. The orders API reads kid from the header and finds the matching public key. It downloaded the keys from the JWKS endpoint earlier and keeps them cached.
  6. It checks the algorithm, the signature, the expiry, the issuer and the audience. All pass, so it handles the request as user 7.
  1. The app sends the same token, meant for orders-api, to the payments API.
  2. The payments API checks the signature with the public key. It is correct, because the same auth server signed it.
  3. The aud claim is orders-api, not payments-api, so it replies 401. Without this check, a token leaked from one API would open every API.
  1. An attacker decodes a token, changes "sub": "7" to "sub": "1", encodes the payload again and keeps the old signature.
  2. The orders API computes the signature check over the new payload. It does not match, so it replies 401. Without the private key, the attacker cannot make a matching signature.
  3. The attacker tries again with "alg": "none" and no signature. The API accepts only ES256, so this fails too.
  1. The auth server creates a new key pair with kid 2026-11 and lists both public keys at the JWKS endpoint.
  2. New tokens are signed with the new key and carry kid 2026-11. Older tokens still carry 2026-10 and still work.
  3. The orders API sees a kid it has not cached, fetches the JWKS again and finds the new key.
  4. Once the longest token lifetime has passed, every token signed with 2026-10 has expired. The old key is removed from the JWKS.

Problems it solves

  • A lookup on every requestThe API checks the signature with a cached public key. No call to the auth server or a database.
  • Many APIs trusting one loginEvery API can check tokens with the public key, and none of them can create tokens.
  • Each API asking who the caller isThe claims travel inside the token: user ID, audience, scopes.
  • Custom token formatsJWT is a standard, with tested libraries in every common language.
  • Changing keys without downtimeThe kid header and the JWKS URL let old and new keys work side by side.

Problems it introduces

  • No way to cancel a token earlyA JWT works until exp. Short lifetimes and refresh tokens are needed.
  • The payload is publicAnyone with the token can read it, so it must hold no secrets or personal data.
  • Easy to check wronglySkipping the algorithm or audience check opens real attacks. Use a library and set every check.
  • SizeA JWT is often 300 to 1000 bytes, sent with every request.
  • Clocks must agreeServers with wrong clocks reject good tokens or accept expired ones.
  • Key managementThe private key must stay secret, and keys must be rotated on a schedule.

Signs tokensauth-server/src/tokens.tsUses the jose library. Only this server holds the private key. The discovery document tells APIs where the public keys are. During a key change, the JWKS response lists both keys.
import { randomUUID } from "node:crypto";
import { Router } from "express";
import { SignJWT, exportJWK, importPKCS8, importSPKI } from "jose";

const issuer = "https://auth.shop.example.com";
const keyId = process.env.SIGNING_KEY_ID!;
const privateKey = await importPKCS8(process.env.SIGNING_PRIVATE_KEY!, "ES256");
const publicKey = await importSPKI(process.env.SIGNING_PUBLIC_KEY!, "ES256");

export function issueAccessToken(userId: string, audience: string, scope: string): Promise<string> {
  return new SignJWT({ scope })
    .setProtectedHeader({ alg: "ES256", typ: "JWT", kid: keyId })
    .setIssuer(issuer)
    .setSubject(userId)
    .setAudience(audience)
    .setIssuedAt()
    .setExpirationTime("15m")
    .setJti(randomUUID())
    .sign(privateKey);
}

export const keyRoutes = Router();

keyRoutes.get("/.well-known/openid-configuration", (_req, res) => {
  res.json({ issuer, jwks_uri: `${issuer}/.well-known/jwks.json` });
});

keyRoutes.get("/.well-known/jwks.json", async (_req, res) => {
  const publicJwk = await exportJWK(publicKey);
  res.set("Cache-Control", "public, max-age=3600");
  res.json({ keys: [{ ...publicJwk, kid: keyId, alg: "ES256", use: "sig" }] });
});
Checks tokensorders-api/src/requireAccessToken.tscreateRemoteJWKSet downloads the public keys, caches them, and fetches again when a token has an unknown kid. jwtVerify runs all five checks. The rejection reason is logged, but never the token.
import { NextFunction, Request, Response } from "express";
import { createRemoteJWKSet, errors, jwtVerify } from "jose";
import { Logger } from "pino";

const issuer = "https://auth.shop.example.com";
const audience = "orders-api";
const authServerKeys = createRemoteJWKSet(new URL(`${issuer}/.well-known/jwks.json`));

export function requireAccessToken(logger: Logger) {
  return async (req: Request, res: Response, next: NextFunction) => {
    const header = req.get("authorization") ?? "";
    const token = header.startsWith("Bearer ") ? header.slice("Bearer ".length) : "";

    try {
      const { payload } = await jwtVerify(token, authServerKeys, {
        algorithms: ["ES256"],
        issuer,
        audience,
        clockTolerance: 30,
      });
      res.locals.userId = payload.sub;
      res.locals.scopes = String(payload.scope ?? "").split(" ");
      next();
    } catch (error) {
      const reason = error instanceof errors.JOSEError ? error.code : "unknown";
      logger.info({ reason, ip: req.ip, path: req.path }, "access token rejected");
      res.status(401).json({ error: "The access token is missing, expired or not valid." });
    }
  };
}
Signs tokenssrc/AuthServer/TokenIssuer.csOnly this server holds the private key. The JWKS is built from a copy that holds just the public part. The discovery document tells APIs where the public keys are. During a key change, the JWKS response lists both keys.
using System.Security.Claims;
using System.Security.Cryptography;
using Microsoft.IdentityModel.JsonWebTokens;
using Microsoft.IdentityModel.Tokens;

namespace AuthServer;

public class TokenIssuer
{
    public const string Issuer = "https://auth.shop.example.com";
    private readonly ECDsaSecurityKey signingKey;
    private readonly ECDsaSecurityKey publicKey;

    public TokenIssuer(IConfiguration configuration)
    {
        var keyId = configuration["SIGNING_KEY_ID"];
        var privateEcdsa = ECDsa.Create();
        privateEcdsa.ImportFromPem(configuration["SIGNING_PRIVATE_KEY"]);

        signingKey = new ECDsaSecurityKey(privateEcdsa) { KeyId = keyId };
        publicKey = new ECDsaSecurityKey(ECDsa.Create(privateEcdsa.ExportParameters(includePrivateParameters: false))) { KeyId = keyId };
    }

    public string IssueAccessToken(Guid userId, string audience, string scope) =>
        new JsonWebTokenHandler().CreateToken(new SecurityTokenDescriptor
        {
            Issuer = Issuer,
            Audience = audience,
            Subject = new ClaimsIdentity([
                new Claim(JwtRegisteredClaimNames.Sub, userId.ToString()),
                new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),
                new Claim("scope", scope),
            ]),
            IssuedAt = DateTime.UtcNow,
            Expires = DateTime.UtcNow.AddMinutes(15),
            SigningCredentials = new SigningCredentials(signingKey, SecurityAlgorithms.EcdsaSha256),
        });

    public object PublicKeys()
    {
        var jwk = JsonWebKeyConverter.ConvertFromECDsaSecurityKey(publicKey);
        return new { keys = new[] { new { kty = jwk.Kty, crv = jwk.Crv, kid = jwk.Kid, alg = "ES256", use = "sig", x = jwk.X, y = jwk.Y } } };
    }
}

public static class KeyEndpoints
{
    public static void MapKeyEndpoints(this WebApplication app)
    {
        app.MapGet("/.well-known/openid-configuration", () =>
            Results.Ok(new { issuer = TokenIssuer.Issuer, jwks_uri = $"{TokenIssuer.Issuer}/.well-known/jwks.json" }));

        app.MapGet("/.well-known/jwks.json", (TokenIssuer issuer, HttpContext http) =>
        {
            http.Response.Headers.CacheControl = "public, max-age=3600";
            return Results.Ok(issuer.PublicKeys());
        });
    }
}
Checks tokenssrc/OrdersApi/TokenCheckSetup.csAuthority makes the JWT bearer handler read the discovery document, download the public keys, check iss, and fetch the keys again when a token has an unknown kid. Audience and ValidAlgorithms add the other checks. The rejection reason is logged, but never the token.
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;

namespace OrdersApi;

public static class TokenCheckSetup
{
    public static void AddAccessTokenChecks(this IServiceCollection services) =>
        services
            .AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
            .AddJwtBearer(options =>
            {
                options.Authority = "https://auth.shop.example.com";
                options.Audience = "orders-api";
                options.MapInboundClaims = false;
                options.TokenValidationParameters.ValidAlgorithms = [SecurityAlgorithms.EcdsaSha256];
                options.TokenValidationParameters.ClockSkew = TimeSpan.FromSeconds(30);
                options.Events = new JwtBearerEvents
                {
                    OnAuthenticationFailed = context =>
                    {
                        context.HttpContext.RequestServices
                            .GetRequiredService<ILogger<JwtBearerEvents>>()
                            .LogInformation("Access token rejected: {Reason}, path {Path}",
                                context.Exception.GetType().Name, context.Request.Path);
                        return Task.CompletedTask;
                    },
                };
            });
}
