Security / Authentication

Access and Refresh Tokens

Two tokens with different jobs: one short-lived for calling APIs, one long-lived for getting new access tokens.

What it is

An access token cannot be cancelled before it expires, so it should live only minutes. Asking the user for their password every 15 minutes is not acceptable, so the auth server also hands out a refresh token.

The refresh token is a long random value, saved on the server as a hash. The client sends it only to the auth server's refresh endpoint, and gets a new access token back. Because the server saves it, the server can revoke it at any time.

With rotation, every refresh also replaces the refresh token, so each one works once. All refresh tokens that come from one login form a family. If a refresh token that was already used shows up again, someone has a copy, and the server revokes the whole family.

TermMeaningIn the example
Access tokenA short-lived JWT sent to APIs with every request.15 minutes
Refresh tokenA long-lived random value, sent only to the auth server to get a new access token.Ends at most 30 days after login
RotationEach refresh returns a new refresh token and marks the old one as used.R1, then R2, then R3

Absolute expiryThe latest time a family can last, however often it is refreshed.30 days after login
Main rule: access tokens are short-lived and go to every API. Refresh tokens are long-lived, go only to the auth server, and work once.

How the two tokens differ

Access tokenRefresh token
FormatSigned JWTRandom value with no meaning
Lifetime5 to 15 minutesDays to weeks, ending at most 30 days after login
Sent toEvery API, on every requestOnly POST /auth/refresh on the auth server
Saved on the serverNoYes, as a hash
Can be revoked at onceNo, it expiresYes
Where a web app keeps itIn memory, in a JavaScript variableIn a cookie: HttpOnly, Secure, SameSite=Strict, Path=/auth
Where a mobile app keeps itIn memoryThe phone's secure storage (Keychain, Keystore)

The cookie's Path=/auth means the browser sends the refresh token only to the auth endpoints, not with every API request. HttpOnly keeps page scripts from reading it.

Cases that need care

CaseWhat happensHow to handle it
Two browser tabs refresh at the same momentBoth send R1. The second looks like reuse, and the user is logged out.The client lets only one refresh run at a time (Web Locks API). The server also accepts reuse within a 10-second grace period.
The network drops after the server rotatedThe client never got R2 and sends R1 again later.Within the grace period it works. After it, the user logs in again. That is the price of reuse detection.
A user stays active for monthsEach refresh would extend the login forever.The family has an absolute expiry, 30 days after login. After that, the user logs in again.
LogoutThe access token in memory is thrown away, but a copy would still work until it expires.Revoke the family and clear the cookie. A copied access token stops within 15 minutes.
"Log out on all devices"Each device has its own family.Revoke every family of the user.

Example flow:

Pick a flow and press Play to follow it through the diagram, step by step.

  1. The web app calls the orders API with its access token, kept in a JavaScript variable.
  2. 15 minutes after it was issued, the access token has expired. The API replies 401.
  3. The app calls POST /auth/refresh. The browser adds the refresh token cookie R1 by itself, because the path matches /auth.
  4. The auth server finds the hash of R1. It is unused, not revoked, and its family is less than 30 days old. The server marks R1 as used and saves a new token, R2, in the same family.
  5. It returns a new access token in the body and sets R2 as the new cookie.
  6. The app repeats the failed request with the new access token. The user notices nothing.
  1. An attacker gets a copy of refresh token R1, for example through malware on the user's computer.
  2. The real app refreshes first. R1 is marked as used, and the app gets R2.
  3. The attacker sends R1. It was used more than 10 seconds ago, so the server knows a copy exists.
  4. The server revokes the whole family, R2 included, and logs an error. The attacker gets 401, and the real user must log in again.
  5. If the attacker had refreshed first instead, the real app's next refresh with R1 would trigger the same check, and the attacker's new token would be revoked with the family. Either way, the copy stops working at the next refresh.
  1. The user has two tabs open. Both get 401 at the same moment, because they share the expired access token.
  2. Without care, both tabs would send R1. The second request would look like reuse, and the user would be logged out.
  3. The client takes a browser lock (Web Locks API) before refreshing. Tab A refreshes and receives R2 in the shared cookie. Tab B waits, then refreshes with R2.
  4. The server also accepts a used token for 10 seconds, for clients without the lock or requests that crossed in flight. It still rotates, but does not revoke the family.
  1. The user presses "Log out". The app calls POST /auth/logout, and the browser adds the refresh token cookie.
  2. The server revokes every token in that family.
  3. It clears the cookie. The app throws away the access token in memory.
  4. A copied access token would still work for up to 15 minutes, because APIs do not look up tokens. That limit is why access tokens are short.

Problems it solves

  • Long-lived tokens that cannot be cancelledAccess tokens last minutes. Logging out revokes the refresh token, and nothing new can be issued.
  • Asking for the password oftenThe client gets new access tokens in the background, for up to 30 days.
  • Not knowing a token was copiedWith rotation, a used refresh token showing up again proves a copy exists.
  • The long-lived secret going everywhereThe refresh token goes only to the auth server, never to APIs or their logs.
  • APIs looking up every tokenAPIs still check access tokens with a public key only. Lookups happen only on refresh, every 15 minutes per user.

Problems it introduces

  • A server-side table againRefresh tokens must be saved, looked up and cleaned up, much like sessions.
  • Race conditionsParallel refreshes from tabs or retries can look like theft. Locks and a grace period are needed.
  • A short gap after logoutA copied access token keeps working until it expires.
  • More client codeThe client must spot 401, refresh once, retry the request and handle a failed refresh by sending the user to log in.
  • Users logged out by mistakeA lost response outside the grace period looks like reuse and ends the login.
Refresh tokensdb/refresh_tokens.sqlOne row per refresh token. Only a hash is saved, so a copy of the table cannot be used. family_id groups the tokens from one login, so one statement can revoke them all. family_expires_at is copied to each row, so the 30-day limit holds however often the family is refreshed.
CREATE TABLE refresh_tokens (
  token_hash         TEXT PRIMARY KEY,
  family_id          UUID NOT NULL,
  user_id            UUID NOT NULL,
  family_expires_at  TIMESTAMPTZ NOT NULL,
  created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  used_at            TIMESTAMPTZ,
  revoked_at         TIMESTAMPTZ
);

CREATE INDEX refresh_tokens_by_family ON refresh_tokens (family_id);
CREATE INDEX refresh_tokens_by_user ON refresh_tokens (user_id) WHERE revoked_at IS NULL;

Clientweb-app/src/tokenClient.tsThe access token lives only in a variable, so it is gone on reload; the first call then refreshes. navigator.locks lets one tab refresh at a time across all tabs, and refreshInFlight makes calls in one tab share a single refresh. The same code serves the TypeScript and C# servers.
let accessToken: string | null = null;
let refreshInFlight: Promise<string> | null = null;

async function refreshAccessToken(): Promise<string> {
  const response = await fetch("https://auth.shop.example.com/auth/refresh", {
    method: "POST",
    credentials: "include",
  });
  if (!response.ok) {
    accessToken = null;
    window.location.assign("/login");
    throw new Error("The login has ended.");
  }

  const body: { accessToken: string } = await response.json();
  accessToken = body.accessToken;
  return body.accessToken;
}

function refreshOnce(): Promise<string> {
  refreshInFlight ??= navigator.locks
    .request("token-refresh", refreshAccessToken)
    .finally(() => {
      refreshInFlight = null;
    });
  return refreshInFlight;
}

function withAccessToken(init: RequestInit, token: string): RequestInit {
  const headers = new Headers(init.headers);
  headers.set("Authorization", `Bearer ${token}`);
  return { ...init, headers };
}

export async function callApi(url: string, init: RequestInit = {}): Promise<Response> {
  const token = accessToken ?? (await refreshOnce());
  const response = await fetch(url, withAccessToken(init, token));
  if (response.status !== 401) return response;

  const newToken = await refreshOnce();
  return fetch(url, withAccessToken(init, newToken));
}
Auth serverauth-server/src/refreshTokens.tsFOR UPDATE locks the token's row, so two refreshes with the same token are handled one after the other. A token used more than 10 seconds ago revokes its whole family. issueAccessToken is the function from the JWT page.
import { createHash, randomBytes, randomUUID } from "node:crypto";
import { Router, Response } from "express";
import { Pool, PoolClient } from "pg";
import { Logger } from "pino";
import { issueAccessToken } from "./tokens";

const cookieName = "refresh_token";
const familyLifetimeDays = 30;
const gracePeriodSeconds = 10;

type StoredRefreshToken = {
  token_hash: string;
  family_id: string;
  user_id: string;
  family_expires_at: Date;
  used_at: Date | null;
  revoked_at: Date | null;
};

function hashToken(token: string): string {
  return createHash("sha256").update(token).digest("hex");
}

async function saveNewRefreshToken(
  transaction: Pool | PoolClient,
  family: { familyId: string; userId: string; familyExpiresAt: Date },
): Promise<string> {
  const refreshToken = randomBytes(32).toString("base64url");
  await transaction.query(
    `INSERT INTO refresh_tokens (token_hash, family_id, user_id, family_expires_at)
     VALUES ($1, $2, $3, $4)`,
    [hashToken(refreshToken), family.familyId, family.userId, family.familyExpiresAt],
  );
  return refreshToken;
}

function setRefreshCookie(res: Response, refreshToken: string, familyExpiresAt: Date): void {
  res.cookie(cookieName, refreshToken, {
    httpOnly: true,
    secure: true,
    sameSite: "strict",
    path: "/auth",
    expires: familyExpiresAt,
  });
}

export async function startTokenFamily(db: Pool, res: Response, userId: string): Promise<string> {
  const family = {
    familyId: randomUUID(),
    userId,
    familyExpiresAt: new Date(Date.now() + familyLifetimeDays * 24 * 60 * 60 * 1000),
  };
  setRefreshCookie(res, await saveNewRefreshToken(db, family), family.familyExpiresAt);
  return issueAccessToken(userId, "orders-api", "orders:read orders:write");
}

export function refreshRoutes(db: Pool, logger: Logger): Router {
  const router = Router();

  router.post("/auth/refresh", async (req, res) => {
    const presentedToken: string | undefined = req.cookies[cookieName];
    const transaction = await db.connect();
    try {
      await transaction.query("BEGIN");
      const { rows: [stored] } = await transaction.query<StoredRefreshToken>(
        "SELECT * FROM refresh_tokens WHERE token_hash = $1 FOR UPDATE",
        [hashToken(presentedToken ?? "")],
      );

      if (!stored || stored.revoked_at || stored.family_expires_at < new Date()) {
        await transaction.query("ROLLBACK");
        logger.info({ ip: req.ip, reason: stored ? "revoked or expired" : "unknown" }, "refresh rejected");
        res.clearCookie(cookieName, { path: "/auth" });
        return res.status(401).json({ error: "The login has ended. Log in again." });
      }

      const secondsSinceUse = stored.used_at ? (Date.now() - stored.used_at.getTime()) / 1000 : null;
      if (secondsSinceUse !== null && secondsSinceUse > gracePeriodSeconds) {
        await transaction.query(
          "UPDATE refresh_tokens SET revoked_at = now() WHERE family_id = $1 AND revoked_at IS NULL",
          [stored.family_id],
        );
        await transaction.query("COMMIT");
        logger.error(
          { userId: stored.user_id, familyId: stored.family_id, ip: req.ip, userAgent: req.get("user-agent") },
          "refresh token used again after the grace period, family revoked",
        );
        res.clearCookie(cookieName, { path: "/auth" });
        return res.status(401).json({ error: "The login has ended. Log in again." });
      }

      if (!stored.used_at) {
        await transaction.query("UPDATE refresh_tokens SET used_at = now() WHERE token_hash = $1", [stored.token_hash]);
      }
      const family = { familyId: stored.family_id, userId: stored.user_id, familyExpiresAt: stored.family_expires_at };
      const newRefreshToken = await saveNewRefreshToken(transaction, family);
      await transaction.query("COMMIT");

      setRefreshCookie(res, newRefreshToken, stored.family_expires_at);
      const accessToken = await issueAccessToken(stored.user_id, "orders-api", "orders:read orders:write");
      logger.info(
        { userId: stored.user_id, familyId: stored.family_id, withinGracePeriod: secondsSinceUse !== null },
        "tokens refreshed",
      );
      res.json({ accessToken, expiresIn: 900 });
    } catch (error) {
      await transaction.query("ROLLBACK");
      throw error;
    } finally {
      transaction.release();
    }
  });

  router.post("/auth/logout", async (req, res) => {
    const presentedToken: string | undefined = req.cookies[cookieName];
    const revoked = await db.query(
      `UPDATE refresh_tokens SET revoked_at = now()
       WHERE family_id = (SELECT family_id FROM refresh_tokens WHERE token_hash = $1)
         AND revoked_at IS NULL
       RETURNING user_id, family_id`,
      [hashToken(presentedToken ?? "")],
    );
    if (revoked.rows[0]) {
      logger.info({ userId: revoked.rows[0].user_id, familyId: revoked.rows[0].family_id, reason: "logout" }, "family revoked");
    }
    res.clearCookie(cookieName, { path: "/auth" });
    res.status(204).end();
  });

  return router;
}
Auth serversrc/AuthServer/RefreshTokenEndpoints.csFOR UPDATE locks the token's row, so two refreshes with the same token are handled one after the other. A token used more than 10 seconds ago revokes its whole family. TokenIssuer is the class from the JWT page.
using System.Security.Cryptography;
using System.Text;
using Dapper;
using Microsoft.AspNetCore.WebUtilities;
using Npgsql;

namespace AuthServer;

record StoredRefreshToken(
    string TokenHash, Guid FamilyId, Guid UserId, DateTime FamilyExpiresAt, DateTime? UsedAt, DateTime? RevokedAt);

public static class RefreshTokenEndpoints
{
    private const string CookieName = "refresh_token";
    private const int FamilyLifetimeDays = 30;
    private static readonly TimeSpan GracePeriod = TimeSpan.FromSeconds(10);

    private static string HashToken(string token) =>
        Convert.ToHexString(SHA256.HashData(Encoding.UTF8.GetBytes(token)));

    private static async Task<string> SaveNewRefreshTokenAsync(
        NpgsqlConnection connection, NpgsqlTransaction? transaction, Guid familyId, Guid userId, DateTime familyExpiresAt)
    {
        var refreshToken = WebEncoders.Base64UrlEncode(RandomNumberGenerator.GetBytes(32));
        await connection.ExecuteAsync(
            """
            INSERT INTO refresh_tokens (token_hash, family_id, user_id, family_expires_at)
            VALUES (@TokenHash, @familyId, @userId, @familyExpiresAt)
            """,
            new { TokenHash = HashToken(refreshToken), familyId, userId, familyExpiresAt }, transaction);
        return refreshToken;
    }

    private static void SetRefreshCookie(HttpResponse response, string refreshToken, DateTime familyExpiresAt) =>
        response.Cookies.Append(CookieName, refreshToken, new CookieOptions
        {
            HttpOnly = true,
            Secure = true,
            SameSite = SameSiteMode.Strict,
            Path = "/auth",
            Expires = familyExpiresAt,
        });

    private static void ClearRefreshCookie(HttpResponse response) =>
        response.Cookies.Delete(CookieName, new CookieOptions { Path = "/auth" });

    public static async Task<string> StartTokenFamilyAsync(NpgsqlDataSource db, TokenIssuer issuer, HttpResponse response, Guid userId)
    {
        var familyExpiresAt = DateTime.UtcNow.AddDays(FamilyLifetimeDays);
        await using var connection = await db.OpenConnectionAsync();
        var refreshToken = await SaveNewRefreshTokenAsync(connection, null, Guid.NewGuid(), userId, familyExpiresAt);
        SetRefreshCookie(response, refreshToken, familyExpiresAt);
        return issuer.IssueAccessToken(userId, "orders-api", "orders:read orders:write");
    }

    public static void MapRefreshTokenEndpoints(this WebApplication app)
    {
        app.MapPost("/auth/refresh", async (HttpContext http, NpgsqlDataSource db, TokenIssuer issuer, ILogger<TokenIssuer> logger) =>
        {
            var presentedToken = http.Request.Cookies[CookieName] ?? "";
            await using var connection = await db.OpenConnectionAsync();
            await using var transaction = await connection.BeginTransactionAsync();

            var stored = await connection.QuerySingleOrDefaultAsync<StoredRefreshToken>(
                """
                SELECT token_hash AS TokenHash, family_id AS FamilyId, user_id AS UserId,
                       family_expires_at AS FamilyExpiresAt, used_at AS UsedAt, revoked_at AS RevokedAt
                FROM refresh_tokens WHERE token_hash = @TokenHash FOR UPDATE
                """,
                new { TokenHash = HashToken(presentedToken) }, transaction);

            if (stored is null || stored.RevokedAt is not null || stored.FamilyExpiresAt < DateTime.UtcNow)
            {
                logger.LogInformation("Refresh rejected from {Ip}: {Reason}",
                    http.Connection.RemoteIpAddress, stored is null ? "unknown" : "revoked or expired");
                ClearRefreshCookie(http.Response);
                return Results.Json(new { error = "The login has ended. Log in again." }, statusCode: 401);
            }

            var timeSinceUse = DateTime.UtcNow - stored.UsedAt;
            if (timeSinceUse > GracePeriod)
            {
                await connection.ExecuteAsync(
                    "UPDATE refresh_tokens SET revoked_at = now() WHERE family_id = @FamilyId AND revoked_at IS NULL",
                    new { stored.FamilyId }, transaction);
                await transaction.CommitAsync();
                logger.LogError("Refresh token for user {UserId} used again after the grace period, family {FamilyId} revoked, IP {Ip}",
                    stored.UserId, stored.FamilyId, http.Connection.RemoteIpAddress);
                ClearRefreshCookie(http.Response);
                return Results.Json(new { error = "The login has ended. Log in again." }, statusCode: 401);
            }

            if (stored.UsedAt is null)
                await connection.ExecuteAsync("UPDATE refresh_tokens SET used_at = now() WHERE token_hash = @TokenHash",
                    new { stored.TokenHash }, transaction);

            var newRefreshToken = await SaveNewRefreshTokenAsync(connection, transaction, stored.FamilyId, stored.UserId, stored.FamilyExpiresAt);
            await transaction.CommitAsync();

            SetRefreshCookie(http.Response, newRefreshToken, stored.FamilyExpiresAt);
            logger.LogInformation("Tokens refreshed for user {UserId}, family {FamilyId}, within grace period: {WithinGracePeriod}",
                stored.UserId, stored.FamilyId, stored.UsedAt is not null);
            return Results.Ok(new
            {
                accessToken = issuer.IssueAccessToken(stored.UserId, "orders-api", "orders:read orders:write"),
                expiresIn = 900,
            });
        });

        app.MapPost("/auth/logout", async (HttpContext http, NpgsqlDataSource db, ILogger<TokenIssuer> logger) =>
        {
            var presentedToken = http.Request.Cookies[CookieName] ?? "";
            await using var connection = await db.OpenConnectionAsync();
            var familyId = await connection.QuerySingleOrDefaultAsync<Guid?>(
                """
                UPDATE refresh_tokens SET revoked_at = now()
                WHERE family_id = (SELECT family_id FROM refresh_tokens WHERE token_hash = @TokenHash)
                  AND revoked_at IS NULL
                RETURNING family_id
                """,
                new { TokenHash = HashToken(presentedToken) });

            if (familyId is not null)
                logger.LogInformation("Family {FamilyId} revoked, reason {Reason}", familyId, "logout");

            ClearRefreshCookie(http.Response);
            return Results.NoContent();
        });
    }
}
